먼저 떠올릴 장면

명세가 필요한 이유

“배열에서 가장 큰 값을 돌려주세요”라는 부탁은 짧아도 확인할 조건이 남는다. 같은 값이 여러 개면 어떻게 할까? 입력이 빈 배열이면 어떻게 할까? 원본을 바꿔도 될까? Process형 문제에는 알고리즘을 아는 능력과 명세를 정확히 구현하는 능력이 모두 필요하다. 공개 예시 하나가 맞는 것은 출발점일 뿐이다. 예시에 없는 최소 크기나 경계값에서도 문제의 조건을 일관되게 적용해야 한다.

이번 자체 제작 연습에서는 행별 최솟값과 최댓값으로 정규화하는 함수, 그리고 정확히 지정된 CNN을 만든다. 실제 문항과의 일치나 출제 예측을 주장하지 않는다. 여기서 정한 빈 입력·상수 행의 처리 규칙은 연습의 명세다. 실제 문제에 다른 처리 규칙이 있으면 그것을 따른다. 여러 상황에 두루 쓸 라이브러리를 만드는 과제와 주어진 조건을 지키는 함수를 만드는 과제는 같지 않다.

문제의 동사를 반환값으로 번역하기

‘정규화하라’라는 단어만 보고 익숙한 스케일러를 불러오지 말자. 이 연습은 ‘각 행에서 최소를 빼고 그 행의 범위로 나눈 배열을 반환하라’고 읽는다. 여기서 각 행은 계산 범위, 나눈다는 말은 연산, 같은 크기는 반환 조건이다. 정규화를 평균 0·표준편차 1로 만드는 작업이라고만 외웠다면 아는 코드를 써도 다른 문제를 풀게 된다.

작은 표 [[2,4,6],[5,5,5]]를 종이에 그리면 조건이 구체화된다. 첫 행의 세 숫자는 한 묶음이고 두 번째 행은 별개다. 첫 행의 최소 2를 두 번째 행에 적용해서는 안 된다. ‘빈 입력도 허용’이라는 문장을 만나면 사람이 없더라도 열 세 개짜리 표는 존재할 수 있다고 읽는다. 반면 열이 0개면 한 행의 최소·최대라는 계산 대상 자체가 없다. [0,3]과 [3,0]을 모두 ‘빈 배열’ 하나로 암기하지 않는 이유다.

낯선 말부터 풀기

원본·결측·상수는 다른 조건이다

원본 보존은 함수가 결과를 돌려준 뒤에도 호출자가 가지고 있던 x의 값이 그대로라는 뜻이다. x의 두 번째 행을 다른 계산에 다시 쓸 수도 있기 때문이다. 결과만 정확하고 원본을 0으로 덮었다면 앞 함수가 뒤 함수의 입력까지 몰래 바꾼다. 그래서 입력 표와 반환 표를 구별하고, 호출 전 복사본과 호출 후 x를 대조한다.

결측값 NaN은 ‘이 칸을 모른다’는 표시, Inf는 유한하지 않은 값, 상수 행은 ‘알고 있는 모든 값이 같다’는 상태다. [5,5,5]의 분모 0과 [5,NaN,5]의 통계 미정은 원인이 다르다. 여기서는 유한 실수만 허용하므로 NaN은 입력 검사에서 거절하고, 상수 행은 명세대로 0으로 바꾼다. 다른 Process가 NaN 보존을 요구한다면 같은 처리를 복사하면 안 된다. 안전한 함수란 모든 예외를 없애는 함수가 아니라 합의된 허용 범위에서 정확히 행동하는 함수다.

작은 배열의 용어

입출력 조건은 함수가 무엇을 받아 어떤 결과를 반환해야 하는지 정한 규칙이다. B는 행 또는 배치의 샘플 수, F는 특성 수다. 크기(shape) [B,F]는 각 행에 F개 값이 있다는 뜻이다. 원소 자료형(dtype)은 float32처럼 값을 저장하는 방식을 말한다. 원본 변경(mutation)은 함수가 받은 자료를 제자리에서 바꾸는 것이다. 경계 사례(edge case)는 최소 크기·상수 배열·크기 1인 축처럼 구현의 허용 범위와 특수 조건을 확인할 입력이다.

테스트에는 구체적인 정답 비교와 불변조건 점검이 있다. 정답 비교는 [2,4,6]→[0,0.5,1]처럼 수를 확인한다. 불변조건은 “출력 배열의 크기가 입력과 같다”, “원본이 유지된다”처럼 모든 허용 입력에서 지킬 성질이다. 많은 입력에서 오류를 내는 코드가 더 정확한 것은 아니다. 문제에서 허용한 입력을 독단적으로 거절하면 그것도 명세 위반이다.

입력 [B,3,8,10]의 3은 RGB 채널이고 8×10은 공간이다. 출력 채널 4는 네 종류의 필터가 각 위치를 읽어 네 장의 특징 지도를 만든다는 뜻이다. 풀링은 각 특징 지도 안의 2×2에서 최대 하나를 남기므로 높이와 너비는 절반이 되지만 특징 지도 수 4는 그대로다. 이 결과를 한 샘플마다 펴야 네 지도에 있는 80개 숫자를 선형층에 넣을 수 있다.

Linear(80,2)는 샘플마다 80개 입력을 각각 가중합하여 두 출력을 만든다. 샘플이 세 개면 같은 가중치 묶음을 세 번 적용하므로 [3,2]다. 배치가 늘어났다고 별도 모델을 세 개 만드는 것은 아니다. 매개변수 수에 B를 곱하지 않는 이유도 이 공유에서 나온다. 그림의 배열 크기와 매개변수 수를 함께 읽으면 ‘출력 원소가 늘면 가중치도 늘어난다’는 혼동을 줄일 수 있다.

정규화·CNN 손계산

행 정규화 함수의 조건을 정하자. 입력은 유한 실수의 2차원 배열, 특성 수는 1 이상, 반환은 입력과 크기가 같은 float64 배열, 상수 행은 0, 원본은 보존한다. 샘플이 없는 [0,F]도 허용한다. 수식은 u_ij=(x_ij-min_i)/(max_i-min_i)이며 i는 행, j는 열이다. [2,4,6]은 최소 2·최대 6·범위 4이므로 [0,2/4,4/4]=[0,0.5,1]이다. [5,5,5]는 0으로 나누지 않고 정해 둔 규칙에 따라 [0,0,0]을 반환한다.

CNN은 합성곱층에서 공간 크기 8×10을 유지하고, 풀링층에서 4×5가 된다. 채널은 합성곱층가 만든 4개이므로 펼친 벡터의 크기는 4×4×5=80이다. 합성곱층 매개변수 수는 4×3×3×3+4=112, 선형층은 80×2+2=162, 전체 학습 매개변수는 274다. ReLU와 풀링층에는 학습 매개변수가 없다. 출력 크기가 2라고 모든 층의 매개변수가 2개인 것은 아니다.

분모와 출력 크기를 생략 없이 유도하기

첫 행은 2−2=0, 4−2=2, 6−2=4를 먼저 계산하고, 공통 범위 6−2=4로 각각 나누어 0, 0.5, 1을 얻는다. 둘째 행은 5−5=0이지만 0/0을 0이라고 계산한 것은 아니다. 0/0은 정의되지 않으므로 별도로 약속한 반환값 0을 쓴 것이다. np.divide의 where는 분모가 0이 아닌 칸만 나눗셈하게 하고 나머지는 out에 준비한 0을 남긴다.

합성곱은 길이 I에 패딩 P를 양쪽에 붙이고 커널 K가 들어갈 시작 위치를 보폭 S 간격으로 센다. 팽창률 1이면 출력 길이는 floor((I+2P−K)/S)+1이다. 높이는 floor((8+2−3)/1)+1=8, 너비는 floor((10+2−3)/1)+1=10이다. 풀링은 높이 floor((8−2)/2)+1=4, 너비 floor((10−2)/2)+1=5다. floor는 소수 부분을 버리고 아래 정수를 고르는 연산이다. Conv 필터 하나는 3채널×3×3=27개 가중치와 편향 1개, 네 필터는 (27+1)×4=112개다. Linear는 출력마다 80개 가중치와 편향 1개이므로 (80+1)×2=162개, 합은 274개다.

PYTHON · 작은 예제로 직접 확인
import numpy as np
import torch
from torch import nn

def row_minmax(x):
    a = np.asarray(x, dtype=np.float64)
    if a.ndim != 2 or a.shape[1] == 0:
        raise ValueError("2D 입력과 최소 한 특성이 필요합니다")
    if not np.isfinite(a).all():
        raise ValueError("유한한 입력만 허용합니다")
    if a.shape[0] == 0:
        return a.copy()
    lo = a.min(axis=1, keepdims=True)
    width = a.max(axis=1, keepdims=True) - lo
    return np.divide(a - lo, width,
                     out=np.zeros_like(a), where=width != 0)

x = np.array([[2, 4, 6], [5, 5, 5]])
before = x.copy()
assert np.allclose(row_minmax(x), [[0, .5, 1], [0, 0, 0]])
assert np.array_equal(x, before)
assert row_minmax(np.empty((0, 3))).shape == (0, 3)
assert np.array_equal(row_minmax([[8]]), [[0]])

net = nn.Sequential(nn.Conv2d(3, 4, 3, padding=1),
                    nn.ReLU(), nn.MaxPool2d(2),
                    nn.Flatten(1), nn.Linear(80, 2))
assert net(torch.zeros(1, 3, 8, 10)).shape == (1, 2)
assert net(torch.zeros(3, 3, 8, 10)).shape == (3, 2)
assert sum(p.numel() for p in net.parameters()) == 274
print("함수 계약과 모델 구조 확인 완료")

단순히 분모에 아주 작은 수를 더하는 구현도 흔하다. 그러나 이 연습에서는 비상수 행의 정확한 범위를 불필요하게 바꾸지 않도록 0인 분모만 따로 처리했다. 상수 행의 모든 값을 0으로 바꾸는 규칙이 정확히 구현되었는지 손계산과 단언문(assertion)으로 확인한다.

테스트를 조건에서 직접 만들어 내기

조건이 ‘행별’이면 두 행의 범위가 크게 다른 자료로 축을 검사하고, ‘상수는 0’이면 [8]처럼 더 줄일 수 없는 입력으로 검사한다. ‘원본 보존’이면 값 비교만으로 끝내지 않고 호출 전후 원본을 비교한다. ‘배치 축 유지’라면 B=1을 골라 크기가 우연히 사라지는지 본다. 테스트 개수를 늘리는 것보다 각 입력이 어느 조건을 검증하는지 설명하는 편이 먼저다.

공개 테스트가 실패하면 전체 함수를 무작정 고치지 말고 실패한 비교식의 좌변과 기대값을 따로 본다. 예를 들어 출력은 맞는데 원본 비교만 False이면 계산 수식보다 제자리 연산을 조사할 근거가 생긴다. 이처럼 실패한 최소 표현식부터 조사하는 접근은 Berkeley Data100의 자동채점 디버깅 안내를 참고했다. 대학 과제의 채점 도구와 HDAT 도구가 같다는 뜻은 아니며, 관찰한 증상을 원인 후보로 좁히는 연습만 적용한다.

자주 헷갈리는 지점

축·상수·배치 경계

axis=0과 axis=1을 사용하면 서로 다른 축을 계산한다. 여기서 열별 최소·최대를 쓰면 각 행을 정규화하라는 요구가 바뀐다. keepdims=True는 행별 통계를 [B,1]로 남겨 원하는 방향으로 브로드캐스팅되도록 한다. 함수 밖에서 만든 배열을 바꿔 버리면 뒤의 셀에서 원본이라고 믿고 쓰는 데이터도 달라진다.

배치 크기 1 테스트가 특히 유용하다. 인자 없이 호출한 squeeze()는 크기 1인 모든 축을 없애서 [1,2]를 [2]로 바꿀 수 있다. 반대로 모델에 입력 높이·너비가 고정이라고 적혀 있다면 임의 크기를 지원하도록 바꾸는 작업이 필수는 아니다. 경계 테스트는 요구한 범위의 최솟값·최댓값과 특수 조건을 확인하는 작업이다. 지원 범위를 무한히 늘릴 필요는 없다.

행 정규화와 훈련 스케일러는 이름이 같아도 다르다

이번 함수는 들어온 한 행 안의 상대 위치를 구한다. 그래서 [2,4,6]과 [20,40,60]은 둘 다 [0,0.5,1]이다. 두 행의 절대 크기 차이를 의도적으로 없앴다. 반면 모델 전처리의 열별 MinMaxScaler는 훈련 집합에서 특성마다 최소·최대를 정해 새 행에도 고정 적용한다. 훈련값 [0,5,10]이라면 기준은 0과 10, 테스트 15는 (15−0)/(10−0)=1.5다. 범위 밖 값이 나오는 것은 훈련의 최댓값보다 크다는 뜻이지 자동 오류가 아니다.

KNN에 두 방식을 번갈아 쓰면 거리의 의미도 달라진다. 행별 처리에서는 절대 크기가 다른 두 기록이 같은 점이 될 수 있고, 열별 고정 처리에서는 훈련 척도에서의 차이가 남는다. 따라서 이 Process 정답을 일반적인 학습 전처리의 정답으로 확대하지 않는다. 실제 데이터에서 어떤 정보를 남길지 결정하는 일과 주어진 함수 명세를 그대로 구현하는 일을 구분한다.

필기 이론: 정의에서 풀이까지

공식에 쓰인 기호가 무엇을 뜻하는지, 어떤 조건에서 그 공식을 쓸 수 있는지 설명합니다. 실습문제와 다른 숫자를 넣은 예제로 계산 과정을 익힙니다. 각 절 끝에는 이 개념을 적용할 문제로 돌아가는 링크가 있습니다.

1. 명세는 수식뿐 아니라 정의역과 반환값까지 포함한다

계산 결과가 [0,0.5,1]로 맞아도 입력 표를 덮어썼거나 지정하지 않은 열까지 바꾸었다면 함수의 약속을 어길 수 있다. Process는 이 약속을 구현하는 문제다. 정의역이라는 말은 받아도 되는 입력의 범위를 뜻한다. 정수만 받을지, 빈 배열을 받을지, NaN을 유지할지부터 정한다. 아래의 ddof=0과 1도 단순한 구현 취향이 아니라 서로 다른 분산 계산을 지정하는 조건이므로 수식과 반환 조건을 함께 읽는다.

함수의 정의역은 허용하는 입력의 집합이다. 같은 수식을 쓰더라도 1차원만 받는 함수와 여러 축의 배열을 받는 함수는 입력 조건이 다르다. 출력의 배열 크기, 자료형, 인덱스, 열 순서뿐 아니라 원본 보존 여부, 빈 입력과 NaN의 처리도 함께 정의한다. 오류가 날 것 같은 모든 입력에 임의로 ValueError를 추가하면 더 안전해 보일 수 있지만, 허용된 입력까지 거절하면 문제를 다르게 구현한 것이다.

먼저 ‘어느 축을 따라 계산할지’를 한국어로 적는다. 행마다 정규화하면 한 행의 통계가 그 행의 모든 열에 적용된다. [B,F] 입력에서 행 평균을 [B,1], 열 평균을 [1,F]로 두면 브로드캐스팅 방향을 알기 쉽다. keepdims는 평균을 구한 축을 크기 1로 남기는 옵션이므로 계산에 사용한 축을 확인하는 데 도움이 된다. 반환값의 숫자가 맞는지와는 별개로, 호출 전 복사본과 호출 후 입력을 비교해 원본이 보존되었는지도 확인한다.

손계산 A: [−2,2,6]의 평균은 2, 편차는 [−4,0,4], 편차제곱합은 32다. 모집단 분산은 32/3, 표준편차는 약 3.266이고 z-score는 약 [−1.225,0,1.225]다. 표본 분산은 32/(3−1)=16, 표준편차는 4라 [−1,0,1]이다. ddof는 분모 N−ddof의 ddof이며 이름만 바꾼 것이 아니다. 유효값 하나에 ddof=1이면 분모가 0이므로 해당 문제의 NaN 정책을 확인한다.

행별 min-max는 별도로 (x−행최소)/(행최대−행최소)다. [−2,2,6]은 범위 8로 나누어 [0,0.5,1]이 된다. 유효값 하나인 행은 분모가 0이므로 이 연습의 “상수 행은 0” 정책으로 처리한다. 표준편차로 나누는 표준화(standardization)과 이름·분모·값 범위가 다르다.

2. 큰 변환 전 점수를 다루는 소프트맥스의 수치 안정성

점수 [1,2]에 1만을 공통으로 더해도 두 클래스 사이의 차이는 1이다. 확률은 그대로여야 하지만 지수함수를 직접 계산하면 컴퓨터가 표현할 수 있는 크기를 넘을 수 있다. 최댓값을 빼는 것은 이 큰 공통 부분을 없애는 방법이다. 둘의 차이를 유지하면서 숫자 규모만 낮추는 것과 상한으로 잘라 차이까지 없애는 것은 다르다. 아래 예에서 지수값의 절대 크기가 아니라 비율이 보존되는지 확인하자.

변환 전 점수(logit) zⱼ의 확률은 pⱼ=exp(zⱼ)/Σₖexp(zₖ)다. 모든 점수에서 같은 m을 빼도 분자와 분모에 exp(−m)이 곱해져 상쇄된다. 따라서 m=max z를 빼면 가장 큰 지수값은 exp(0)=1이고 나머지는 1 이하가 되어 오버플로를 피한다. 최댓값은 클래스 축을 따라 구한다. 여러 샘플에서 최댓값 하나만 구하는 대신 행별 최댓값을 사용하면, 원래 값이 작은 행의 수치가 불필요하게 더 작아지는 것도 피할 수 있다.

손계산 B: [700,700+log4]에서 최댓값을 빼면 [−log4,0], 지수값은 [1/4,1], 합은 5/4, 확률은 [1/5,4/5]다. [−20,−20]도 최댓값을 빼면 [0,0]이므로 확률은 [1/2,1/2]다. 공통으로 더해진 값의 크기가 달라도 점수 차이가 같으면 확률은 같다. NaN이나 Inf는 이 유도에서 가정한 유한한 실수가 아니므로 문항에서 거절하라고 하면 계산 전에 검사한다. 큰 수를 임의의 작은 상한값으로 제한하면 두 점수의 차이가 바뀌므로 같은 해법이 아니다.

3. 합성곱 출력 크기와 학습 매개변수 수는 따로 계산한다

출력 크기는 커널을 몇 위치에 놓았는지를, 파라미터 수는 그 계산을 위해 보관할 서로 다른 가중치가 몇 개인지를 묻는다. 같은 도장을 큰 종이에 여러 번 찍는다고 도장의 무늬 수가 늘지는 않는 것과 비슷하다. 아래 예에서 B가 1에서 8로 커지면 출력 원소 수는 8배지만 Conv의 가중치는 그대로다. 공간 크기 공식, 채널 연결 수, BN의 학습값을 각각 계산한 뒤 합치면 서로 다른 숫자를 섞지 않을 수 있다.

한 축의 입력 길이를 I, 커널 크기를 K, 패딩을 P, 보폭을 S, 팽창률을 D라고 하자. 팽창률은 커널 원소 사이의 간격을 늘리므로 유효 커널 폭은 Keff=D(K−1)+1이다. 패딩을 추가한 뒤 길이는 I+2P다. 커널 시작점은 0,S,2S,… 중 커널 끝이 영역 안에 들어오는 위치여야 한다. 따라서 마지막으로 허용되는 보폭의 배수는 floor((I+2P−Keff)/S)이고, 0에서 시작하는 위치를 더해 출력 크기는 floor((I+2P−Keff)/S)+1이다. 가로와 세로는 따로 계산한다.

입력이 [B,2,11,13], Conv2d가 2→6이고 K=3, S=2, P=1이면 출력 높이는 floor((11+2−3)/2)+1=6, 너비는 7이다. 출력 [B,6,6,7]의 원소 수는 B에 따라 달라져도 학습 파라미터 수는 변하지 않는다. 편향이 있으면 커널 가중치 6×2×3×3=108개와 출력 채널별 편향 6개를 더해 114개다. 뒤의 BatchNorm2d(6)는 γ와 β를 각각 6개 학습하므로 12개이고, ReLU는 0개다. 총 126개다.

누적 평균·분산(running mean/variance)은 저장되는 상태지만 기울기로 갱신하는 학습 파라미터는 아니다. PyTorch BatchNorm은 학습 가능한 선형 변환과 누적 통계 상태를 구분한다.

풀링은 공간 크기를 줄여도 채널 수를 줄이지 않는다. Flatten(1)은 B를 남기고 나머지 축을 펼친다. 위 출력의 공간 축을 평균하여 1×1로 만들면 Linear의 입력 크기는 6이다. 명세에 없는 BN이나 Dropout은 파라미터 수뿐 아니라 실제 동작도 바꾸므로 추가하지 않는다.

26.4 수치 함수: 수치적으로 안정적인 소프트맥스

exp(1000)은 컴퓨터가 저장할 수 있는 범위를 넘을 수 있다. 그러나 softmax는 점수의 절대 크기가 아니라 차이의 지수 비율이다. [1000,1000+ln2]는 [0,ln2]와 같은 확률 [1/3,2/3]을 가져야 한다.

큰 로짓(logit)에 exp를 직접 적용하면 오버플로가 발생한다. 행별 최댓값을 뺀다.

PYTHON 예시
def stable_softmax(x, axis=-1):
    x = np.asarray(x, dtype=np.float64)
    if x.size == 0:
        raise ValueError("softmax 입력은 비어 있을 수 없습니다")
    if not np.isfinite(x).all():
        raise ValueError("softmax 입력은 finite여야 합니다")
    shifted = x - np.max(x, axis=axis, keepdims=True)
    exp_x = np.exp(shifted)
    denom = np.sum(exp_x, axis=axis, keepdims=True)
    return exp_x / denom

Micro-test:

PYTHON 예시
p = stable_softmax(np.array([[1000.0, 1001.0], [0.0, 0.0]]), axis=1)
assert np.isfinite(p).all()
assert np.allclose(p.sum(axis=1), 1.0)
assert np.allclose(p[1], [0.5, 0.5])

try:
    stable_softmax([np.inf, 0.0])
except ValueError:
    pass
else:
    raise AssertionError("non-finite 입력을 거절해야 합니다")

첫 검사는 빈 배열과 NaN/Inf를 거절한다는 이 함수의 정의역이다. max(axis,keepdims=True)는 각 계산 묶음의 최대값을 길이 1 축으로 남겨 같은 묶음 전체에서 빼게 한다. 최대값을 빼면 가장 큰 지수는 exp(0)=1이라 overflow를 피한다. 분자·분모에 같은 exp(−max)가 곱해져 비율은 보존된다.

공개 테스트의 row sum=1은 확률 정규화를, finite는 수치 안정성을, 두 점수가 같은 행의 0.5는 대칭성을 확인한다. 세 검사는 서로 대신하지 않는다. 1 차원과 2 차원의 axis 의미도 각각 읽는다. Inf를 작은 수로 바꾸면 정의역을 몰래 넓히면서 점수 차이까지 바꾸므로 여기서는 명시한 오류가 맞다.

26.5 선택한 열의 표준화

지정된 열만 표준화하고 나머지는 그대로 남기려면 통계를 계산할 열과 결과를 저장할 표를 분리한다. 유효값 [2,4,6]은 평균 4, 모집단 표준편차 √(8/3), 표본 표준편차 2 라서 ddof 선택에 따라 결과가 다르다.

문제가 표본 표준편차 ddof=1인지 모집단 표준편차 ddof=0인지 지정할 수 있다. 그대로 따른다.

PYTHON 예시
def standardize_selected(df, columns, ddof=0):
    out = df.copy()
    for c in columns:
        if c not in out.columns:
            raise KeyError(c)
        mean = out[c].mean()
        std = out[c].std(ddof=ddof)
        if pd.isna(std):
            continue
        s = out[c]
        out[c] = s.where(s.isna(), 0.0) if std == 0 else (s - mean) / std
    return out

copy는 호출자의 원본을 지킨다. 열 존재 검사는 없던 열을 새로 만들지 않게 한다. mean·std는 그 열의 유효값을 사용하고 ddof는 분모 N−ddof를 정한다. 표준편차가 NaN이면 현재 코드의 보존 규칙에 따라 넘어간다. std=0 일 때 s.where(s.isna(),0.0)는 결측 위치는 남기고 실제 상수값만 0으로 만든다.

예를 들어 [7,7,NaN]은 [0,0,NaN]이 된다. 무조건 out[c]=0을 쓰면 모르는 값도 실제 0으로 바뀐다. 수식 결과의 평균·분산뿐 아니라 원래 인덱스·열 순서·선택하지 않은 값과 호출 전 입력이 그대로인지 별도로 검사한다.

26.6 IQR로 이상치 표시하기·범위 제한하기

[0,2,4,6,20]의 Q1=2,Q3=6이라 IQR=4, 1.5 배 경계는 −4와 12다. 값 20을 이상이라고 표시할지,12로 바꿀지,그 행을 없앨지는 세 가지 다른 요청이다. 아래 함수는 그중 명시한 동작만 한다.

PYTHON 예시
def iqr_bounds(s, factor=1.5):
    q1, q3 = s.quantile([0.25, 0.75])
    iqr = q3 - q1
    return q1 - factor * iqr, q3 + factor * iqr

def clip_iqr_column(df, column, factor=1.5):
    out = df.copy()
    lo, hi = iqr_bounds(out[column], factor)
    out[column] = out[column].clip(lo, hi)
    return out

요구사항이 “이상치가 있는 행 제거”라면 값을 경계값으로 대체해서는 안 된다. 이상치 표시, 값 대체, 행 제거는 서로 다른 작업이다.

quantile은 정렬 위치와 보간 규칙으로 경계를 구한다. factor는 IQR을 몇 배 확장할지 정하는 수이고 표준편차가 아니다. clip은 범위 안 값은 그대로, 작은 값은 하한, 큰 값은 상한으로 바꾸며 행 수를 줄이지 않는다. 입력을 copy 한 뒤 열별 경계를 적용해야 원본 변경 금지 조건을 지킨다.

IQR=0이면 하한·상한이 같은 값이 될 수 있다. 그때도 ‘전부 이상이라 삭제’처럼 규칙을 추가하지 않는다. 전처리용 경계라면 학습자료에서 경계를 구해 새 자료에도 적용하지만, 주어진 입력 자체의 IQR을 반환하는 Process 함수라면 그 명세를 따른다.

26.7 PIL crop·layout

너비 8·높이 5인 사진에서 왼쪽 2,위 1,오른쪽 6,아래 4를 자르면 가로 4·세로 3이다. PIL 좌표는 x,y 순서지만 배열 모양은 높이,너비 순서여서 두 표기를 한 번에 외우면 바꾸기 쉽다.

PYTHON 예시
def pil_crop_rgb_array(image, left, upper, right, lower):
    from PIL import Image
    if not isinstance(image, Image.Image):
        raise TypeError("image는 PIL.Image.Image여야 합니다")
    if not (0 <= left < right <= image.width and 0 <= upper < lower <= image.height):
        raise ValueError("crop 좌표가 이미지 범위를 벗어났습니다")
    return np.asarray(image.convert("RGB").crop((left, upper, right, lower)))

문제가 흑백 모드 보존을 요구하면 .convert('RGB')를 넣지 않는다. 반환할 배열의 채널 수와 모드를 확인한다.

isinstance는 PIL 이미지라는 입력 종류를 검사한다. 좌표 검사에서 left<right,upper<lower 여야 빈 이미지가 되지 않고 right≤width,lower≤height 여야 바깥으로 나가지 않는다. 오른쪽·아래쪽은 포함하지 않으므로 폭은 right−left다.

convert('RGB')는 이 예제의 반환을 세 채널로 통일하고 crop은 지정 영역, np.asarray는 픽셀 배열을 얻는다. 이 순서로 얻는 모양은 [crop_height,crop_width,3]이다. 별도 문제가 원래 모드를 보존하라고 하면 RGB 변환을 가져다 붙이면 안 된다. 흑백은 채널 축이 없고 RGBA는 4 채널일 수 있기 때문이다.

26.8 정확한 CNN 명세 옮기기

모델 구현 문제는 더 좋은 성능의 새 구조를 제안하는 문제가 아니다. 층 목록을 한 줄씩 옮기면서 각 줄 뒤의 [B,C,H,W]를 기록한다. 32×32 RGB 입력에서 처음 padding1의 k3은 크기를 유지하고, 풀링은 16×16으로 줄이며, 다음 padding0의 k3은 14×14가 된다.

예시 명세(독자 문제):

순서 layer 설정
1 Conv2d 3→16, K=3, S=1, P=1
2 ReLU
3 MaxPool2d K=2, S=2
4 Conv2d 16→32, K=3, S=1, P=0
5 ReLU
6 AdaptiveAvgPool2d 1×1
7 Linear 32→4

정답은 표의 구조를 그대로 구현한 것이다. BN, Dropout, Conv 층을 임의로 추가하지 않는다.

PYTHON 예시
class SpecCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, kernel_size=3, stride=1, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(kernel_size=2, stride=2),
            nn.Conv2d(16, 32, kernel_size=3, stride=1, padding=0),
            nn.ReLU(),
            nn.AdaptiveAvgPool2d((1, 1)),
        )
        self.classifier = nn.Linear(32, 4)

    def forward(self, x):
        x = self.features(x)
        return self.classifier(x.flatten(1))

spec_model = SpecCNN()
assert spec_model(torch.zeros(2, 3, 32, 32)).shape == (2, 4)
assert spec_model(torch.zeros(1, 3, 40, 48)).shape == (1, 4)

AdaptiveAvgPool2d(1)은 각 채널의 공간 평균 하나를 남겨 [B,32,1,1]로 만든다. flatten(1)은 [B,32], 마지막 Linear는 [B,4]다. 따라서 40×48 입력도 중간 크기는 달라도 같은 출력 4 개로 갈 수 있다. 이는 전역 풀링이 연결 폭을 고정해 주기 때문이다.

더미 테스트 두 개는 정사각형·직사각형과 B=2·1을 함께 점검한다. shape가 맞아도 층 순서, bias 기본값, kernel과 padding이 명세와 같은지는 별도로 읽는다. 중간 Dropout 하나를 더 넣으면 shape는 같아도 학습 동작이 달라져 정답 구조가 아니다.

26.9 층별 출력 크기·매개변수 수 요약

출력 원소 수와 학습할 가중치 수를 분리해서 센다. 같은 3×3 커널은 이미지 모든 위치에서 재사용하므로 이미지가 커져도 커널 가중치는 늘지 않는다. 반면 Linear의 입력 폭을 늘리면 각 출력에 연결할 가중치가 늘어난다.

층 출력 크기 매개변수 수
Linear(I,O) [...,O] I×O+O
Conv1d(Ci,Co,K) 길이는 공식 Co×Ci/groups×K + Co
Conv2d(Ci,Co,Kh,Kw) H/W 공식 Co×Ci/groups×Kh×Kw + Co
BatchNorm(C) 입력과 같은 크기 학습 매개변수 2C + 별도 누적 통계
ReLU/Pool/Dropout 각 연산의 규칙에 따른 크기 0
Embedding(V,D) 입력 shape+D V×D
단방향 LSTM (batch_first=True) 시퀀스 출력 [B,T,H], 여기서 H는 은닉 크기 층마다 게이트 4개의 가중치·편향

I는 Linear 입력 수,O는 출력 수이며 I×O 개의 연결과 출력별 bias O개가 있다. Conv의 Ci·Co는 입력·출력 채널, groups는 채널 연결을 나누는 묶음 수다. 각 출력은 Ci/groups개 채널만 보므로 그만큼 커널을 센다. BN은 채널마다 곱하는 γ와 더하는 β를 학습해 2C개이며 running 통계는 저장 상태이지 학습 파라미터는 아니다.

LSTM은 입력·망각·후보·출력의 네 계산에 입력 및 은닉 연결이 필요하므로 4 배가 등장한다. 여러 층에서는 다음 층 입력 폭이 첫 층 F와 다를 수 있다. Embedding은 V개 항목마다 D개 좌표를 저장해 V×D다. ‘출력이 커졌으니 파라미터도 그 원소 수만큼’이라고 세지 않는다.

26.10 데이터 분할 방법 선택·구현

차량 한 대의 여러 행을 섞으면 처음 보는 차량 시험이 아니라 이미 본 차량의 다른 기록 시험이 된다. 반대로 같은 차량의 미래가 목적이면 과거→미래 조건이 먼저다. 분할 이름을 고르기 전에 테스트에서 무엇이 새로운지 한 문장으로 적는다.

데이터 splitter
IID 회귀 KFold
IID 분류 StratifiedKFold
새로운 그룹 GroupKFold/GroupShuffleSplit
미래 시점 TimeSeriesSplit 또는 직접 지정한 시간순 분할
PYTHON 예시
from sklearn.model_selection import KFold, StratifiedKFold, GroupKFold, TimeSeriesSplit

kf = KFold(n_splits=5, shuffle=True, random_state=42)
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
gkf = GroupKFold(n_splits=5)

def conservative_window_gap(lookback, horizon, label_span=1):
    """연속 end-index window 행에서 train label과 valid input까지 분리하는 보수적 gap."""
    if lookback < 1 or horizon < 0 or label_span < 1:
        raise ValueError("window 계약 오류")
    return lookback + horizon + label_span - 2

# 독립적인 시계열 행 예시
tscv_rows = TimeSeriesSplit(n_splits=5)
# 이미 만든 연속 window 행 예시. 숫자 20처럼 고정하지 말고 문제 계약에서 계산한다.
tscv_windows = TimeSeriesSplit(
    n_splits=5,
    gap=conservative_window_gap(lookback=20, horizon=40, label_span=1),
)

# 사용 예: for tr, va in skf.split(X, y): ...
# group: for tr, va in gkf.split(X, y, groups): ...
# time: 정렬된 X에 for tr, va in tscv_rows.split(X): ...

TimeSeriesSplit은 데이터를 섞지 않으므로 입력을 먼저 시간순으로 정렬해야 한다. 윈도(window) 문제에서는 원시 시점과 정답 인덱스를 기준으로 분할을 직접 지정하면 이해하기 쉽다. 구간을 나누는 지점에서 이미 관측 가능한 과거 기록을 검증 입력으로 다시 사용하는 것은 허용될 수 있으므로 위 gap은 보수적으로 설정한 예다. 핵심은 정답이 포함하는 시간 구간, 예측 간격(horizon), 실제 예측 시점에 맞춰 미래 정보나 정답이 유출되지 않는지 assertion으로 확인하는 것이다.

KFold는 독립 행을, StratifiedKFold는 독립 분류 행의 비율을, GroupKFold는 집단의 중복을 다룬다. TimeSeriesSplit은 현재 행 순서를 시간순이라고 가정하므로 시간값·동률 정책을 먼저 정렬해야 한다. shuffle과 random_state는 무작위 분할 재현을 돕지만 누수 자체를 검사하지 않는다.

위 코드의 gap 함수는 연속 윈도를 stride=1로 늘어놓고, 각 샘플이 쓰는 입력부터 정답 구간까지 완전히 겹치지 않게 하는 보수적 길이 L+H+label_span−2를 계산한다. L=20, H=40, label_span=1이면 59다. 이 숫자를 모든 시계열 문제의 필수값으로 외우지 않는다.

TimeSeriesSplit의 gap은 넘기는 자료의 ‘행’ 단위이고, 원시 시점 한 행과 윈도 한 행은 다를 수 있다. 실제 예측 순간 이미 알려진 과거 입력의 재사용은 허용될 수 있으므로 입력 끝·정답 시점·정답이 공개되는 시점으로 직접 검산하는 것이 더 분명하다.

26.11 특성 선택·추출의 최소 구현

기존 열을 남기는 선택기와 새 축을 만드는 추출기를 구별하면 필요한 정답 y와 출력 폭을 추적할 수 있다. 같은 fit_transform 한 줄이라도 무엇을 학습하는지는 다르다.

PYTHON 예시
from sklearn.feature_selection import VarianceThreshold, SelectKBest, mutual_info_classif, SelectFromModel
from sklearn.linear_model import LogisticRegression
from sklearn.decomposition import PCA
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis
from sklearn.cluster import DBSCAN

variance_selector = VarianceThreshold(threshold=0.0)
univariate_selector = SelectKBest(mutual_info_classif, k=20)
model_selector = SelectFromModel(LogisticRegression(penalty="l1", solver="liblinear"))
pca = PCA(n_components=0.95, random_state=42)
lda = LinearDiscriminantAnalysis(n_components=None)
dbscan = DBSCAN(eps=0.5, min_samples=5)

모두 훈련 폴드에서 학습한다. LDA에는 정답 y가 필요하며 최대 차원은 min(n_features, n_classes-1)이다. DBSCAN의 -1은 잡음을 뜻하는 라벨이며, 군집 번호는 정답 클래스와 같은 의미가 아니다.

VarianceThreshold는 거의 변하지 않는 열을 걸러내고 SelectKBest는 점수 상위 k 열을 고른다. mutual_info_classif는 분류 정답과의 연관을 사용한다. L1 모델을 넣은 SelectFromModel은 학습 중 작아지거나 0이 된 계수를 기준으로 기존 열을 고른다. PCA는 분산축을, LDA는 클래스 구별축을 만든다.

LDA의 판별축은 F와 C−1 중 작은 수를 넘지 못한다. 클래스 평균 C개가 전체 평균 주위에 놓인 차이 방향의 독립성이 최대 C−1이기 때문이다. DBSCAN은 밀집한 점들을 묶고 −1을 잡음으로 표시하며 이것이 자동으로 고장 라벨을 뜻하지 않는다. 어떤 선택·추출도 훈련 폴드에서 적합하고 검증에는 정한 변환만 적용한다.

26.12 Process 시간 운영

전체 시간 170 분에서 한 함수의 경계조건에 40 분을 쓰면 나머지 모델 학습·제출에 쓸 시간이 그만큼 사라진다. A/B/C는 문제의 공식 난이도가 아니라 지금 내가 완료할 수 있는 속도에 대한 작업 분류다.

각 문항을 A/B/C로 표시한다.

  • A: 즉시 풀 수 있음 → 먼저
  • B: 확인하면 풀 수 있음 → 두 번째
  • C: 디버깅이나 모델 구현이 오래 걸림 → Problem의 첫 기준 모델 완성 후

한 문항에 15분 이상 막히면 현재 코드와 오류를 저장하고 이동한다. 쉬운 7문항을 잃고 어려운 1문항에 매달리지 않는다.

A는 바로 구현할 수 있는 것, B는 확인 후 해결할 것, C는 시간이 크게 필요한 것이다. 15 분 동안 새로운 검산 결과가 없으면 현재 코드·실패 입력·다음 검색어를 저장하고 넘어가면 재개 비용이 줄어든다. 함수 하나를 포기한다는 뜻이 아니라 먼저 유효한 Problem 파일과 쉬운 점수를 확보하는 순서다. 운영 시간을 기록해 다음 모의에서 자신의 실제 속도로 분류를 수정한다.

  1. 먼저 무엇을 봐야 하나? bias=True인 Conv와 affine=True인 BN의 학습 매개변수만 센다.

    풀이: Conv 출력 8개 각각 입력 채널 3개 ×5×5=75개의 가중치를 가지므로 총 600개이고, bias 8개를 더해 608 개다. BN의 γ 8개·β 8개를 더해 624 개다. ReLU는 0 개다.

    정답: Conv 8×3×5×5+8=608, BN 학습 매개변수 16, 합 624. 누적 평균·분산은 학습 매개변수가 아니다.

    왜? 커널은 공간에서 공유되고 BN은 채널별 곱·덧셈 두 숫자만 학습한다.

    헷갈리기 쉬운 부분: padding2나 입력 H/W를 곱하지 않는다. running 평균·분산은 학습 파라미터에서 제외한다.

    한 줄 기억: 커널 600+bias8+BN16=624다.

  2. 먼저 무엇을 봐야 하나? 두 logit이 같고 유한한 1000이다.

    풀이: 최댓값 1000을 빼면[0,0], 지수는[1,1], 합 2로 나누면[0.5,0.5]다.

    정답: [0.5,0.5].

    왜? 공통 최댓값을 빼도 지수 비율은 보존되고 큰 지수의 overflow를 피한다.

    헷갈리기 쉬운 부분: exp1000을 직접 계산한 Inf/Inf는 안정적 해법이 아니다.

    한 줄 기억: 같은 두 점수의 softmax는 반반이다.

    풀이: min(F,C−1)=min(5,2)=2를 계산한다. 실제 평균 관계의 랭크가 낮으면 더 적을 수 있다.

    정답: min(5,3-1)=2.

    왜? 세 클래스 평균의 전체 평균 대비 차이는 가중합 0이어서 독립 방향이 최대 둘이다.

    헷갈리기 쉬운 부분: 클래스 3 개라고 3 축을 만들지 않는다. PCA의 주성분 수와도 다르다.

    한 줄 기억: LDA 상한은 min(F,C−1)이다.

    풀이: 시간을 실제 숫자·datetime으로 해석하고 오름차순 정렬과 같은 시각의 정책을 확정한다. 그 후 분할의 입력·정답 공개 시점이 의도한 미래 조건인지 검산한다.

    정답: 행이 실제 시간순으로 안정 정렬돼 있어야 한다.

    왜? 분할기는 문자 시간을 올바른 순서로 자동 정렬해 주는 도구가 아니기 때문이다.

    헷갈리기 쉬운 부분: random_state만 설정해도 시간 누수가 사라지는 것은 아니다.

    한 줄 기억: 시간 분할 전에 실제 시간 순서를 보장한다.

    왜? 요구된 함수와 동일한 동작인지가 평가 대상이지 자유로운 모델 개선이 아니기 때문이다.

    한 줄 기억: shape가 같아도 추가 층은 명세 변경이다.

  1. 먼저 볼 조건: 행별 최소·최대와 상수 행은 0이라는 명세를 본다.

    단계 풀이: 첫 행 최소 −3, 최대 5 → 범위 8 → 분자 [0,4,8] → [0,0.5,1]. 한 값 7은 최대=최소다.

    정답: 첫 행의 범위는 8이므로 [0,4/8,8/8]=[0,0.5,1]이다. [7]은 한 원소 상수 행이므로 [0]이다. 단일 특성을 특별히 오류로 처리하면 이 명세에서 허용한 입력을 거절하게 된다.

    왜: 상수 행의 0은 나눗셈 결과가 아니라 지정된 예외 규칙이다.

    헷갈리기 쉬운 부분: 특성 하나라고 입력을 거절하면 허용된 [B,1]을 지원하지 못한다.

    한 줄 기억: 상수와 잘못된 입력을 구분한다.

    단계 풀이: Conv 뒤 [B,4,8,12] → 2×2 풀링 뒤 [B,4,4,6] → 한 행 4×4×6=96개.

    정답: 풀링 뒤 [B,4,4,6], 펼친 벡터의 크기 96이다. Linear(80,2)와 행렬 곱에 필요한 차원이 맞지 않아 연결할 수 없다. 다만 원 명세가 8×10만 허용한다면 8×12 지원 실패 자체가 오답은 아니다.

    왜: 선형층은 입력 열 수 80에 맞춘 가중치를 가지고 있다.

    헷갈리기 쉬운 부분: 원 명세의 허용 범위 밖인 8×12를 못 받는다고 원 답안이 틀린 것은 아니다.

    한 줄 기억: 새 입력의 평탄화 크기를 구한 뒤 선형층과 비교한다.

    단계 풀이: 호출 전 입력을 복사한다. 함수를 호출한다. 입력과 복사본을 비교한다. 다르면 제자리 수정 연산을 찾아 바꾼다.

    정답: 안 된다. 원본 보존도 출력값만큼 중요한 명세다. 입력 복사 후 계산하거나 원본을 제자리에서 바꾸지 않는 연산을 사용하고, 호출 전후에 원본이 같은지 다시 검사해야 한다.

    왜: 원본을 다시 사용할 뒤 계산의 자료를 보존해야 한다.

    헷갈리기 쉬운 부분: 반환 배열이 맞다는 한 조건이 다른 명세 위반을 상쇄하지 않는다.

    한 줄 기억: 원본 보존도 정답의 일부다.
