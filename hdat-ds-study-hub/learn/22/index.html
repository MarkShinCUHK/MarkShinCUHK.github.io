먼저 떠올릴 장면

같은 세 온도라도 [10,20,30]은 올라가는 흐름이고 [30,20,10]은 내려가는 흐름이다. 평균은 둘 다 20이라 평균 하나만 남기면 이 차이를 잃는다. 순환 신경망 RNN은 값을 시간순으로 읽으면서 지금까지의 정보를 숫자 묶음으로 갱신한다. 새 입력뿐 아니라 이전까지 만든 요약도 다음 계산에 넣기 때문에 순서의 영향을 표현할 수 있다.

그 숫자 묶음이 은닉 상태다. 은닉 상태는 실제 온도도 정답도 아니며 모델 안에서 계산한 중간 특징이다. 마지막 상태를 Linear 헤드에 넣어 미래 온도를 예측할 수 있다. 상태 h와 가중치 W를 구별하자. h는 어떤 시계열을 읽는지에 따라 매 시점 달라지고, W는 읽는 규칙으로 모든 시점에 공유된다. 학습은 손실을 보고 W를 바꾸며, 순전파는 그 W를 사용해 h를 계산한다.

문제는 오래된 정보가 여러 번의 갱신을 거치며 약해지거나 덮일 수 있다는 점이다. LSTM과 GRU는 이전 정보와 새 정보를 얼마나 섞을지 정하는 연속적인 조절값, 즉 게이트를 사용한다. 1D CNN은 상태를 순서대로 갱신하는 대신 작은 시간 구간의 무늬를 같은 필터로 읽는다. 이번 장은 각 모델의 이름보다 어떤 정보를 어떻게 남겨 마지막 예측에 전달하는지에 초점을 맞춘다.

낯선 말부터 풀기

게이트는 사람이 붙인 정답이 아니라 학습한 비율이다

이전 기록이 2이고 80%를 남기기로 했다면 남는 값은 0.8×2=1.6이다. 새 후보가 −0.4이고 25%를 기록하면 0.25×(−0.4)=−0.1을 더한다. 이 비율 0.8과 0.25가 게이트의 역할이다. 게이트마다 현재 입력과 이전 은닉 상태에 선형 변환을 적용하고 시그모이드로 0과 1 사이의 수를 만든다. 예를 들어 시그모이드에 넣기 전 점수인 게이트 로짓이 0이면 시그모이드가 0.5여서 절반을 통과시킨다. 사람이 모든 시점의 비율을 따로 정하지 않는다.

LSTM에는 계속 보관할 셀 상태 c와 다음 층에 보여 줄 은닉 상태 h가 있다. 장부 c의 일부를 읽어 h를 만들므로 둘은 같지 않다. 세 게이트는 남길 비율 f, 기록할 비율 i, 보여 줄 비율 o이고, 후보 g는 비율이 아니라 새로 기록할 내용이다. 후보는 음수일 수 있다. ‘모든 내부 값은 확률’이라고 읽으면 셀 상태 계산을 잘못하게 된다.

GRU에서 리셋 게이트(reset gate)는 새 후보값(candidate)을 만들 때 이전 상태를 얼마나 반영할지 조절하고, 갱신 게이트(update gate)는 이전 은닉 상태와 새 후보값을 어떻게 섞을지 조절한다. PyTorch 표기에서는 h_new=(1−z)⊙n+z⊙h_old이므로 z가 클수록 기존 상태를 더 남긴다. 어떤 설명은 반대로 계수를 정의하므로 게이트 이름만 외우지 말고 갱신식에서 어느 항에 곱하는지 읽는다. LSTM과 달리 별도의 c 상태를 반환하지 않는 점도 코드에서 드러난다.

기본 RNN은 h_t=φ(W_x x_t+W_h h_(t−1)+b)다. x_t는 t시점 입력, h_t는 새 은닉 상태, W_x는 입력을 읽는 가중치, W_h는 이전 상태를 읽는 가중치다. φ는 tanh 같은 비선형 활성함수다. tanh는 음수·양수의 구별을 남기면서 값을 −1과 1 사이로 눌러 주며, 입력 0은 0으로 바꾼다. 다대일(many-to-one)은 입력 구간 전체에서 출력 하나를 만들고, 다대다(many-to-many)는 시점마다 출력을 만든다. 시퀀스-투-시퀀스(sequence-to-sequence)는 입력과 출력의 길이가 다를 수도 있는 구조를 뜻한다.

BPTT는 시간을 따라 펼친 연산 그래프에서 역전파하는 방법이다. 새로운 미분법이 아니라 같은 가중치를 반복 사용한 그래프에 연쇄법칙을 적용하는 것이다. 야코비안(Jacobian)은 여러 입력의 작은 변화가 여러 출력에 미치는 변화율을 모은 미분 행렬이다. 이 행렬이 반복해서 곱해지면서 기울기가 점점 작아지는 기울기 소실(vanishing gradient)이나 지나치게 커지는 기울기 폭발(exploding gradient)이 생길 수 있다. LSTM에서는 c_t=f_t⊙c_(t−1)+i_t⊙g_t, h_t=o_t⊙tanh(c_t)를 쓴다. f는 이전 셀 상태를 유지할 비율, i는 새 후보값 g를 기록할 비율, o는 셀 상태를 은닉 상태에 반영할 비율이다. ⊙는 같은 위치끼리 곱하기다. 후보값 g에는 보통 tanh를 적용하며, 시그모이드(sigmoid)를 적용하는 세 게이트의 값과 구별한다.

시간을 따라 펼친 상자는 같은 규칙의 재사용이다

그림에서 첫 입력 x₁과 시작 상태 h₀가 h₁을 만들고, x₂와 h₁이 h₂를 만든다. 상자가 두 개라고 가중치 세트가 두 개인 것은 아니다. 같은 W를 두 번 사용한 계산을 시간을 따라 펼쳐 그린 것이다. 입력의 어떤 시점이 바뀌면 그 뒤 상태가 연쇄적으로 바뀔 수 있다. 손실에서 뒤로 갈 때도 그 연결을 따라 기울기를 계산하고, 여러 시점에서 같은 W를 사용한 기여를 모은다.

독립적인 두 차량 구간을 한 배치에 넣어도 각 표본의 상태는 따로 있다. 차량 A의 마지막 상태를 무관한 차량 B의 시작 상태로 넘기면 다른 사건의 기억을 섞게 된다. 이어진 한 시계열을 배치로 나눠 상태를 계속 넘기는 설계는 가능하지만, 독립 구간을 섞는 일반 학습과 구별해 순서와 초기화 정책을 정해야 한다.

핵심 기억 — 상태 h는 시계열을 읽으며 바뀌는 중간값이고 가중치 W는 시점마다 공유하는 규칙이다. LSTM은 h 외에 c를 따로 둔다.

숫자로 끝까지 따라가기

상태에서 실제 예측까지 한 단계를 더 이어 보자

아래 RNN의 h₂≈0.9830은 정답 온도 0.9830도를 바로 뜻하지 않는다. 예를 들어 헤드가 예측=2h₂+1이면 2×0.9830+1=2.9660이 최종 예측이다. 정답이 3이면 제곱오차는 (2.9660−3)²≈0.001156이다. 이 손실을 뒤로 미분하면 헤드뿐 아니라 h₂를 만든 공유 가중치에도 기울기가 전달된다. 상태가 왜 예측에 쓸모 있는 요약으로 학습되는지 이 연결로 이해한다.

GRU의 혼합도 한 좌표로 확인할 수 있다. PyTorch 표기의 이전 상태 2, 후보 −1, 갱신 게이트 z=0.75라면 (1−0.75)×(−1)+0.75×2=1.25다. z가 큰 만큼 이전 2를 많이 남겼다. LSTM의 c처럼 별도 보관 상태를 반환하지 않지만, 과거와 새 후보의 반영량을 조절한다는 문제의식은 연결된다.

상태가 숫자 하나인 스칼라 RNN에서 W_x=1, W_h=0.5, b=0, h₀=0, 입력 x₁=1,x₂=2, 활성함수는 tanh라고 하자. h₁=tanh(1)≈0.7616이다. 두 번째 시점에서 활성함수를 적용하기 전 값은 2+0.5×0.7616=2.3808, h₂=tanh(2.3808)≈0.9830이다. 두 번째 입력이 들어갈 때 처음 입력의 영향은 h₁을 통해 전달된다. h₂는 두 입력의 단순 평균도, 마지막 입력 2 자체도 아니다.

LSTM 한 좌표의 이전 c=2, f=0.8, i=0.25, 후보값 g=−0.4, o=0.5라고 하자. 남긴 기억은 0.8×2=1.6, 새 기록은 0.25×(−0.4)=−0.1, 새 c는 1.5다. 은닉 상태는 0.5×tanh(1.5)≈0.4526이다. 셀 상태 1.5와 은닉 상태 약 0.4526을 구분하지 않고 같은 값으로 저장하면 다음 계산이 달라진다. 게이트들이 이전 상태와 새 정보를 조절하는 가운데 셀 상태를 덧셈으로 갱신하는 구조가 장기 정보 전달을 돕는다. 그렇다고 기울기 소실이 완전히 사라지는 것은 아니다.

PyTorch에서 배치 B=2, 길이 T=4, 입력 특성 F=3, 은닉 차원 H=5, 한 층 단방향 LSTM을 batch_first=True로 만들면 입력 [2,4,3], 시점별 출력 [2,4,5], h_n과 c_n은 각각 [1,2,5]다. batch_first는 입력·출력의 배치 축에만 적용되며 상태 텐서는 [층수×방향수,B,H]다. 기본값 False이면 배치 입력·출력은 [T,B,F], [T,B,H]다. 이 예처럼 투영 층이 없는 한 층 LSTM의 파라미터 수는 4HF+4H²+8H=60+100+40=200이다. 두 편향 묶음까지 세었다.

PYTHON · 작은 예제로 직접 확인
import torch

torch.manual_seed(3)
x = torch.randn(2, 4, 3)  # [B,T,F]
rnn = torch.nn.LSTM(3, 5, batch_first=True)
seq, (h, c) = rnn(x)
assert seq.shape == (2, 4, 5)
assert h.shape == c.shape == (1, 2, 5)
assert torch.allclose(seq[:, -1, :], h[-1])
assert sum(p.numel() for p in rnn.parameters()) == 200
head = torch.nn.Linear(5, 1)
pred = head(h[-1])
target = torch.zeros(2, 1)
loss = torch.nn.functional.mse_loss(pred, target)
loss.backward()
torch.nn.utils.clip_grad_norm_(rnn.parameters(), 1.)
conv = torch.nn.Conv1d(3, 6, kernel_size=3, padding=1)
cnn_out = conv(x.permute(0, 2, 1))
assert cnn_out.shape == (2, 6, 4)
print(seq.shape, h.shape, pred.shape, cnn_out.shape)

이 예에서 마지막 시점의 출력과 h_n이 같다는 성질은 단방향이고, 모든 표본의 유효 길이가 같으며, 패딩이 없다는 조건에서 사용했다. 일반적인 양방향·가변 길이 코드에 그대로 적용하지 않는다.

팁: 코드를 읽는 기준 — 코드의 seq[:, -1, :]와 h[-1] 일치 검사는 단방향·같은 유효 길이·패딩 없음 조건이다. 양방향에서는 방향별 최종 상태를 h_n에서 꺼낸다.

시험 문제로 연결하기

긴 기억의 어려움은 미분을 여러 번 곱할 때 드러난다

한 시점에서 이전 상태의 변화가 다음 상태에 0.5배 전달되는 단순한 상황을 생각하자. 네 시점을 거슬러 전달되는 기울기에는 0.5⁴=0.0625가 곱해진다. 반대로 매번 2배이면 2⁴=16이다. 앞 시점까지의 학습 신호가 아주 약해지는 것이 소실, 너무 커지는 것이 폭발이다. 실제 RNN은 행렬과 활성함수 미분을 곱하므로 더 복잡하지만 반복 곱이라는 원리는 같다. Stanford CS231n의 RNN 슬라이드에서 시간별 계산 그래프와 LSTM의 셀 경로를 비교해 볼 수 있다.

LSTM의 덧셈 경로는 이전 셀 상태를 남기기 쉽게 하지만 f가 계속 작으면 기억도 여전히 줄어든다. 클리핑은 큰 기울기를 제한하고, 게이트는 정보의 갱신 구조를 바꾼다. 둘을 같은 해결책으로 부르지 않는다.

양방향 RNN은 입력 구간을 앞뒤로 읽어 얻은 특징을 합친다. 마지막 층의 두 최종 상태는 h_n에서 방향별로 꺼내 합쳐야 한다. seq[:,-1,:]에서 역방향에 해당하는 절반은 전체 입력 구간을 읽은 최종 요약과 같지 않다. RNN·GRU는 상태로 h_n을, LSTM은 (h_n,c_n) 튜플을 반환한다. PyTorch LSTM 문서는 방향·층·투영 설정에 따른 텐서 형태와 내장 드롭아웃의 적용 위치를 명시한다.

길이가 서로 다른 입력을 0으로 채워 패딩했다면 마지막 행이 실제 마지막 관측은 아닐 수 있다. RNN에는 실제 길이를 기록한 lengths와 패딩 부분을 제외해 처리하는 압축 시퀀스(packed sequence)를 사용하거나, 과제에 맞게 유효한 마지막 시점을 선택한다. 0은 실제 측정값일 수도 있으므로 단순히 0이라고 자동으로 무시되지는 않는다. 1D CNN 입력은 [B,F,T]이므로 permute(0,2,1)로 바꾸고, 풀링 이후의 출력 형태는 RNN의 예측 헤드와 동일하게 만들 수 있다. 과거 구간 전체를 요약해 하나를 예측하는 모델과 매 시점 즉시 예측하는 모델은 이용할 수 있는 정보의 범위가 다르다.

자주 헷갈리는 지점

길이를 맞춘 0은 실제 관측과 다르게 취급해야 한다

관측 길이가 2인 [4,5]를 길이 4 배치에 맞춰 [4,5,0,0]으로 만들면 마지막 두 0은 자리 채움이다. RNN에 길이를 알려 주지 않으면 0도 실제 입력처럼 두 번 처리하므로 마지막 상태가 5를 읽은 직후 상태와 달라질 수 있다. 실제 센서가 0을 측정할 수도 있어 값만 보고 구별할 수 없다. lengths와 압축 시퀀스 같은 별도 정보가 필요한 이유다. 그리고 batch_first=True여도 최종 상태의 축은 [층수×방향수,B,H]라는 반환 계약을 따른다.

batch_first=True라고 h_n까지 [B,층수,H]로 읽지 않는다. PyTorch 다층 RNN의 dropout 인수는 마지막 층을 제외한 층 사이 출력에 적용되므로 한 층 모델에서 같은 효과를 기대하면 안 된다. GRU가 파라미터가 적다는 이유로 항상 성능이 낮은 것도, LSTM이 더 복잡하다는 이유로 항상 성능이 높은 것도 아니다. 양방향 구조는 이미 모두 관측된 과거 입력 구간을 뒤로 읽는 상황에는 사용할 수 있다. 하지만 현재 시점의 출력이 아직 도착하지 않은 미래 값을 참고한다면 누수다. 1D CNN도 양쪽에 대칭으로 패딩하면 각 시점에서 미래의 이웃 값을 참고할 수 있으므로, 실시간 출력에는 현재와 과거만 참조하는 인과적 커널 배치를 검토한다.

흔한 오해 — 시계열 배치 순서를 섞는 것과 각 창 안 시간 순서를 섞는 것은 다르다. 상태를 다음 배치로 이어 쓰는 모델이면 배치 연결 순서도 지켜야 한다.

정의와 유도 과정부터 문제 풀이까지

필기 이론: 정의에서 풀이까지

공식에 쓰인 기호가 무엇을 뜻하는지, 어떤 조건에서 그 공식을 쓸 수 있는지 설명합니다. 실습문제와 다른 숫자를 넣은 예제로 계산 과정을 익힙니다. 각 절 끝에는 이 개념을 적용할 문제로 돌아가는 링크가 있습니다.

1. RNN은 시간을 따라 같은 함수를 반복한다

한 문장을 읽을 때 앞부분을 전부 다시 복사하기보다 지금까지의 요약을 갱신한다고 생각하자. RNN의 h가 이 요약이다. 아래 예에서는 직전 상태에 0.5를 곱해 현재 입력과 더하고 ReLU를 적용한다. 입력 -1만 보았을 때와 이전 상태 2까지 함께 보았을 때 계산이 달라진다. 시점마다 달라지는 것은 입력과 상태이고, 반복해서 쓰는 가중치는 같다. 긴 시퀀스에서 파라미터 수와 연산량이 다르게 변하는 이유다.

기본 RNN의 h_t=φ(W_xx_t+W_hh_(t−1)+b)에서 x_t는 F차원인 현재 입력, h_t는 H차원인 현재 은닉 상태다. W_x는 [H,F], W_h는 [H,H] 크기이며 모든 시점에서 같은 값을 공유한다. 이전 정보를 원본 배열 그대로 저장하지 않고 예측에 필요한 요약 정보 h로 바꾼다. 시점이 늘어나면 반복 계산은 늘지만 시점마다 새 가중치를 추가하지는 않는다.

손계산 예 A: 스칼라를 사용하는 ReLU RNN에서 h₀=0,W_x=1,W_h=0.5,b=0이고 입력은 [2,−1,3]이라고 하자. h₁=ReLU(2)=2, h₂=ReLU(−1+0.5×2)=0, h₃=ReLU(3+0.5×0)=3이다. 입력값이 같아도 이전 상태가 다르면 결과가 달라진다. 다대일(many-to-one) 방식은 최종 상태나 여러 상태를 집계한 값으로 입력 구간 전체에 대한 출력 하나를 만든다. 다대다(many-to-many) 방식은 각 시점의 h_t마다 출력한다.

‘시계열 모델’이라는 이름만으로 언제 어떤 출력을 내야 하는지 알 수는 없다.

BPTT는 RNN의 계산을 시간 순서로 펼친 그래프에 연쇄법칙을 적용하는 방법이다. 단순한 선형 반복에서 시점마다 미분값이 0.6이라면, 10시점 전까지 역전파할 때 기울기에 곱해지는 값은 0.6^10≈0.00605다. 시점마다 1.4라면 1.4^10≈28.93으로 커진다. 실제 RNN에서는 행렬과 활성함수의 도함수가 곱해져 더 복잡하지만, 기울기 소실과 폭발의 기본 원리는 같다. 기울기 클리핑은 지나치게 큰 값을 제한할 수 있지만 이미 작아진 기울기를 복원하지는 않는다.

2. LSTM의 세 게이트와 두 상태를 구분한다

노트에 남겨 둘 내용과 지금 다른 사람에게 말할 내용을 구분하듯, LSTM도 기억 c와 밖으로 전달할 상태 h를 나눈다. 망각 게이트는 이전 기록을 남길 비율, 입력 게이트는 새 후보를 쓸 비율, 출력 게이트는 저장한 내용에서 내보낼 비율이다. 아래 식은 이전 것 남기기 + 새것 쓰기 → 밖으로 내보내기 순서다. 게이트마다 상태의 각 위치에 서로 다른 비율이 적용되며, 모든 위치를 한 숫자로만 여닫는 문은 아니다.

LSTM은 셀 상태(cell state) c와 은닉 상태(hidden state) h를 구분한다. 망각 게이트(forget gate) f, 입력 게이트(input gate) i, 출력 게이트(output gate) o는 보통 시그모이드로 0과 1 사이의 값을 만든다. 후보값(candidate) g는 tanh로 새로 기록할 내용을 만든다. c_t=f_t⊙c_(t−1)+i_t⊙g_t, h_t=o_t⊙tanh(c_t)다. ⊙는 같은 위치끼리 곱하는 연산이다. 선형 계산 묶음이 네 개라고 게이트도 네 개라고 외우기보다는 세 게이트와 한 후보값으로 이해한다.

손계산 예 B: c_old=3,f=0.6,i=0.4,g=−0.5,o=0.8이면 이전 상태에서 유지하는 값은 1.8이고 새로 기록하는 값은 −0.2이므로 c_new=1.6이다. 은닉 상태는 0.8×tanh(1.6)≈0.7373이다. 셀 상태와 은닉 상태는 같은 값이 아니며 출력 게이트 값이 없으면 은닉 상태의 수치를 결정할 수 없다. 셀 상태를 덧셈으로 갱신하는 구조는 여러 시점에 걸쳐 기억을 전달하는 데 도움이 되지만, 망각 게이트 값이 계속 작으면 정보는 여전히 줄어든다. LSTM이 기울기 소실을 완전히 없앤다는 말은 지나치게 강한 주장이다.

PyTorch LSTM이 한 층, 단방향, 투영 없음, bias=True 조건이면 입력 쪽 가중치는 4HF개, 은닉 상태 쪽 가중치는 4H²개다. 두 편향 묶음 bias_ih와 bias_hh가 각각 4H개이므로 총 파라미터 수는 4HF+4H²+8H다. F=2,H=4이면 32+64+32=128개다. 교재가 합쳐진 편향 묶음 하나만 쓰면 4H만 추가하는 표기일 수 있으므로 PyTorch 계산과 조건을 맞춘다. 다층에서는 두 번째 층의 입력 크기가 앞층의 H×방향 수로 바뀌므로 첫 층 공식에 단순히 층 수를 곱하지 않는다.

3. GRU는 다른 방식으로 과거와 새 후보를 섞는다

PyTorch의 갱신식에서 이전 상태가 2, 후보가 -1, z=0.8이면 새 상태는 (1−0.8)×(−1)+0.8×2=1.4다. z=0이면 전부 후보, z=1이면 전부 이전 상태라는 양끝을 대입하면 기호의 역할을 기억하기 쉽다. 리셋 게이트는 이 마지막 혼합 비율이 아니라 후보를 만드는 과정에서 과거를 참고하는 정도를 정한다. 두 게이트가 작용하는 위치를 구분한 뒤 파라미터 세 묶음의 계산을 읽자.

GRU는 별도의 셀 상태를 반환하지 않고 은닉 상태 하나를 갱신한다. 리셋 게이트(reset gate) r은 후보값을 만들 때 이전 상태를 얼마나 사용할지 조절하고, 갱신 게이트(update gate) z는 기존 상태와 후보값 n을 섞는다. PyTorch 표기의 h_new=(1−z)⊙n+z⊙h_old에서는 z가 클수록 과거 상태를 더 남긴다. 다른 교재에서 z의 역할을 반대로 정의하면 식도 달라질 수 있으므로 이름보다 어느 항에 곱하는지를 읽는다.

PyTorch의 한 층·단방향 GRU에서 기본 파라미터 수는 3HF+3H²+6H다. 같은 F=2,H=4이면 24+48+24=96개로 위 LSTM보다 적다. 상태와 게이트를 계산하는 수가 다르기 때문이다. 파라미터가 적으면 계산량이나 과적합 측면에서 유리할 수 있지만 모든 데이터에서 더 빠르거나 정확하다는 보장은 없다. 실제 연산 구현, 시퀀스 길이, 배치 크기, 최적화 방식과 검증 결과를 살펴봐야 한다.

LSTM과 GRU의 수식은 구현별 차이를 확인하는 기준이다.

4. 입력·시점별 출력·최종 상태는 축 구성이 다르다

동영상에서 모든 프레임의 요약을 모은 결과와, 마지막 프레임까지 본 뒤 남은 요약은 다르다. RNN의 output은 시점별 상태를 모은 것이고 h_n은 층·방향별 마지막 상태다. 그래서 output에는 시간 축 T가 있지만 h_n의 첫 축에는 층 수와 방향 수가 들어간다. 아래의 [3,7,8]과 [4,3,4]를 어떤 묶음을 저장한 배열인가로 읽어 보자. batch_first를 켰다고 모든 반환값의 첫 축이 배치가 되는 것은 아니다.

batch_first=True이면 입력 크기는 [B,T,F], 시점별 출력 크기는 [B,T,DH]다. D는 방향 수로 단방향이면 1, 양방향이면 2다. 층 수를 M이라고 하면 h_n의 크기는 [MD,B,H]다. 투영을 사용하지 않는 LSTM의 c_n도 같은 크기다. batch_first는 h_n의 첫 축을 B로 바꾸는 설정이 아니다. 시점별 출력은 마지막 층의 모든 시점 정보를, 최종 상태는 모든 층의 마지막 상태를 반환하기 때문에 축 구성이 다르다.

예를 들어 B=3,T=7,F=2,H=4,M=2,D=2이면 시점별 출력의 크기는 [3,7,8]이고 h_n과 c_n은 각각 [4,3,4]다. 시퀀스 길이 7은 최종 상태의 첫 축에 포함되지 않는다. 단방향이고 패딩이 없으면 마지막 층의 h_n[-1]과 output[:,-1,:]가 같을 수 있지만 양방향에서는 주의해야 한다. 마지막 시점 출력의 역방향 절반은 뒤에서 읽기 시작한 첫 위치의 상태이므로, 전체 구간을 역방향으로 읽은 요약과는 다르다. 마지막 층에서 두 방향의 최종 상태를 h_n에서 꺼내 합친다.

PyTorch RNN·GRU·LSTM의 내장 dropout 인수는 다층 모델의 층 사이 출력에 적용된다. 이 인수만으로 마지막 층 뒤에 드롭아웃이 추가되지는 않는다. 따라서 2층 모델에서는 첫 층 출력과 둘째 층 입력 사이의 연결에 적용된다. 한 층이면 층 사이의 연결이 없으므로 같은 효과가 없다. 모든 시점의 순환 연결에 같은 드롭아웃이 독립적으로 적용된다는 뜻도 아니다.

5. 패딩·양방향 구조·Conv1d에서 미래 정보를 사용하지 않는 조건

이 절의 세 문제를 따로 구분하자. 패딩은 없는 관측을 계산에서 제외하는 문제, 양방향 구조는 예측 시각에 허용된 관측만 읽는 문제, Conv1d 축 변환은 센서 종류와 시간 위치를 바르게 놓는 문제다. 0으로 채웠다고 자동 제외되지 않고, 뒤에서 읽는다고 무조건 미래 정보도 아니다. CNN1D도 대칭 커널이 현재 위치의 오른쪽 값을 볼 수 있으므로 모델 이름보다 각 출력이 실제로 읽는 시점을 확인한다.

길이가 다른 시퀀스를 0으로 패딩하면 RNN은 그 0도 입력으로 처리할 수 있다. 실제 길이가 4인데 길이 7로 맞췄다면 마지막 상태는 원래 네 관측 뒤에 패딩 세 개까지 처리한 결과일 수 있다. lengths와 패킹된 시퀀스(packed sequence)를 사용하면 실제 관측만 처리하도록 할 수 있다. 0이 실제 센서값일 수도 있으므로 값이 0이라는 이유만으로 자동으로 가려지지는 않는다.

이미 모두 관측된 과거 창으로 미래 하나를 예측한다면 창을 양방향으로 읽어도 미래 정보가 추가되는 것은 아니다. 그러나 시점 t에서 즉시 출력해야 하는 모델이 t+1 관측을 읽으면 예측 시점에 알려진 정보만 사용한다는 인과적(causal) 조건을 위반한다. 같은 양방향 구조라도 출력 시점이 어디인지에 따라 허용 여부가 달라진다. 양방향이라는 이름만으로 무조건 누수라고 단정하지 않는다.

Conv1d는 채널을 둘째 축, 길이를 셋째 축으로 받으므로 [B,T,F]에 permute(0,2,1)을 적용해 [B,F,T]로 바꾼다. F개 센서 종류를 채널로 두고 작은 시간 구간을 옮겨 가며 계산한다. 입력 [3,7,2]는 [3,2,7]이 되고 커널 길이가 3, 패딩이 1, 보폭이 1, out_channels가 5이면 출력 크기는 [3,5,7]이다. 대칭 패딩을 사용하면 시점별 출력이 오른쪽의 미래 관측을 참조할 수 있다. 따라서 현재까지의 정보만으로 실시간 출력을 만들어야 할 때는 왼쪽에만 패딩하는 등의 설계가 필요하다.

전체 과거 구간을 요약하는 모델과 시점마다 실시간으로 출력하는 모델을 다시 구분한다.

공식 근거: PyTorch RNN, pack_padded_sequence, Conv1d. 배열 크기에 쓰이는 B·T·F·H, 방향 수, 층 수를 먼저 정의한 뒤 계산한다.

22.2 기본 RNN

온도를 하나씩 읽으면서 최근 변화의 요약을 갱신한다고 생각하자. 단순한 계산 규칙을 새 상태 = 0.5 × 이전 상태 + 현재 온도로 정하고 처음 상태를 0으로 두면, 온도 [2,4,6]을 읽은 상태는 차례로 2, 5, 8.5가 된다. 마지막 8.5에는 앞에서 읽은 온도의 영향도 남아 있다. 실제 RNN에서는 이런 요약 방법의 가중치를 데이터로 학습하고, 상태도 숫자 하나가 아니라 여러 숫자로 된 벡터다.

h_t = φ(W_x x_t + W_h h_{t-1} + b).

여기서 t는 지금 읽는 시점, x_t는 지금 들어온 F개의 값, h_{t-1}은 직전까지 읽은 내용을 담은 H개의 값, h_t는 갱신한 상태다. W_x는 현재 입력을, W_h는 이전 상태를 새로운 상태의 크기에 맞춰 변환한다. b는 편향이고 φ는 tanh 같은 활성함수다. 입력 특성 수 F와 은닉 상태 크기 H는 달라도 된다. 입력 10개를 상태 32개로 요약했다면 시점마다 32개의 상태 값이 나온다.

같은 파라미터를 모든 시점에서 공유한다. 다대일(many-to-one)은 마지막 은닉 상태 또는 여러 은닉 상태의 집계로 하나의 값을 예측하고, 다대다(many-to-many)는 시점마다 출력을 낸다. 시퀀스 대 시퀀스(sequence-to-sequence)는 입력과 출력 길이가 다를 수 있다.

BPTT는 시간축 역전파라는 뜻이다. 마지막 예측이 틀렸다면 마지막 연산뿐 아니라 그 상태를 만든 이전 시점의 연산까지 거슬러 올라가 가중치의 수정 방향을 계산한다. 같은 가중치를 여러 시점에서 사용했으므로 각 사용 지점에서 생긴 기울기를 모아 갱신한다.

왜 오래전 입력의 영향은 배우기 어려울까? 연쇄법칙 때문에 거슬러 가는 단계마다 미분값이 곱해진다. 단순한 스칼라 예에서 매 단계의 미분이 0.5라면 10단계를 거친 값은 0.5¹⁰ ≈ 0.00098로 작아진다. 매 단계 2라면 2¹⁰ = 1024로 커진다. 전자를 기울기 소실, 후자를 기울기 폭발이라고 한다. 실제 벡터 RNN에서는 가중치 행렬과 활성함수의 미분이 함께 영향을 주므로 특정 가중치 하나만 보고 판정할 수 없다. 기울기 자르기(clipping)는 폭발을 완화하지만 사라진 장기 신호를 복구하는 방법은 아니다.

22.3 LSTM

기본 RNN은 내용을 저장하는 일과 지금 밖으로 내보내는 일을 하나의 상태에 맡긴다. LSTM은 오래 전달할 내용을 담는 셀 상태 c와 현재 시점의 출력 역할을 하는 은닉 상태 h를 나눈다. 게이트는 신경망이 계산하는 0과 1 사이의 숫자다. 0에 가까우면 해당 내용을 적게 전달하고 1에 가까우면 많이 전달한다.

각 계산의 역할은 다음과 같다.

  • 망각 게이트(forget gate) f_t: 이전 셀 상태를 얼마나 유지할지 조절
  • 입력 게이트(input gate) i_t: 새 후보값을 얼마나 기록할지 조절
  • 후보값(candidate) g_t: 새로 기록할 내용
  • 출력 게이트(output gate) o_t: 셀 상태에서 은닉 상태로 얼마나 전달할지 조절

c_t = f_t ⊙ c_{t-1} + i_t ⊙ g_t
h_t = o_t ⊙ tanh(c_t)

⊙는 같은 위치의 원소끼리 곱한다는 뜻이다. 상태의 한 위치에서 이전 기억이 2, 망각 게이트가 0.8, 입력 게이트가 0.25, 새 후보값이 0.4라면 새 셀 상태는 0.8×2 + 0.25×0.4 = 1.7이다. 먼저 이전 내용 1.6을 남기고 새 내용 0.1을 더했다. 출력 게이트까지 0.5라면 은닉 상태는 0.5×tanh(1.7) ≈ 0.468이다. 셀에 보관한 1.7과 밖으로 전달한 약 0.468은 같은 값이 아니다.

한 가지 표준 표기는 다음과 같다.

f_t=σ(W_f[x_t,h_{t-1}]+b_f)
i_t=σ(W_i[x_t,h_{t-1}]+b_i)
g_t=tanh(W_g[x_t,h_{t-1}]+b_g)
o_t=σ(W_o[x_t,h_{t-1}]+b_o)

[x_t,h_{t-1}]는 두 벡터를 이어 붙인 것이고, σ는 값을 01로 바꾸는 sigmoid다. 후보값 g는 tanh를 거쳐 -11의 값을 가질 수 있다. 게이트 i·f·o가 세 개라고 해서 선형 계산도 세 묶음인 것은 아니다. 후보값을 만드는 계산까지 네 묶음이 필요하므로 아래의 4H가 등장한다.

입력 크기 F, 은닉 크기 H인 단방향 단층 LSTM은 입력-은닉 가중치 4H×F, 은닉-은닉 가중치 4H×H와 구현에 따른 편향을 갖는다. PyTorch는 bias_ih, bias_hh 두 편향 묶음을 저장하므로 파라미터 수를 계산할 때 둘 다 포함한다.

셀 상태(cell state)를 덧셈으로 갱신하는 구조가 장기간의 기울기 전달을 돕는다. 다만 기울기 소실을 완전히 없앤다고 단정하지 않는다.

예를 들어 F=10, H=32인 단층·단방향 PyTorch LSTM의 파라미터 수는 4×32×10 + 4×32×32 + 2×4×32 = 5632다. 배치 크기와 입력 길이는 이 계산에 넣지 않는다. 더 많은 표본·시점을 처리해도 같은 가중치를 반복 사용하기 때문이다. 층을 추가하면 다음 층의 입력 크기가 달라지고, 양방향이면 방향별 가중치가 따로 생기므로 조건을 먼저 확인해야 한다.

22.4 GRU

하나의 은닉 상태로 기억을 갱신하는 GRU에서는 갱신 게이트가 이전 상태와 새 후보 중 얼마를 반영할지 조절하고, 리셋 게이트는 후보를 계산할 때 이전 상태를 얼마나 사용할지 조절한다. 가령 이전 상태 2를 75%, 새 후보 -0.4를 25% 반영하면 새 상태는 0.75×2 + 0.25×(-0.4) = 1.4다. 이는 혼합의 직관을 위한 예다. 교재에 따라 갱신 게이트 z와 1-z를 붙이는 쪽이 반대일 수 있으므로 기호 이름만 외우지 말고 실제 식에서 어떤 항에 곱하는지 읽는다.

갱신 게이트(update gate)와 리셋 게이트(reset gate)를 사용하며, 별도 셀 상태 없이 은닉 상태를 갱신한다. LSTM보다 파라미터가 적고 빠를 수 있다. 어느 쪽이 항상 우월한 것은 아니므로 검증 결과와 제한 시간을 보고 결정한다.

같은 F=10, H=32의 단층·단방향이고 두 편향을 쓰면 PyTorch GRU는 세 계산 묶음이므로 3×32×10 + 3×32×32 + 2×3×32 = 4224개다. LSTM의 5632개보다 적다는 것은 이 설정의 크기 비교일 뿐, 정확도 순위를 뜻하지 않는다. 같은 검증 구간과 학습 예산에서 비교해야 모델을 바꾼 효과를 판단할 수 있다.

22.5 PyTorch 시퀀스 모델

아래 모델은 입력 구간 하나당 출력 하나를 만드는 다대일 구조다. cell은 상태 갱신 방법, hidden은 상태에 담을 숫자 수, layers는 위아래로 쌓을 순환 층 수다. 길이가 T라고 해서 층도 T개인 것은 아니다. batch_first=True는 입력·시점별 출력의 축을 [B,T,특성]으로 정하지만, 최종 상태 h_n의 축 순서는 바꾸지 않는다. h_n은 [층 수×방향 수,B,H]다.

PYTHON 예시
class SequenceRNN(nn.Module):
    def __init__(self, n_features, out_dim, hidden=64, layers=1,
                 cell="gru", bidirectional=False, dropout=0.0):
        super().__init__()
        rnn_cls = {"rnn": nn.RNN, "gru": nn.GRU, "lstm": nn.LSTM}[cell]
        self.rnn = rnn_cls(
            input_size=n_features,
            hidden_size=hidden,
            num_layers=layers,
            batch_first=True,
            bidirectional=bidirectional,
            dropout=dropout if layers > 1 else 0.0,
        )
        self.directions = 2 if bidirectional else 1
        self.head = nn.Linear(hidden * self.directions, out_dim)

    def forward(self, x):                # [B,T,F]
        _, state = self.rnn(x)
        # LSTM state=(h_n,c_n), RNN/GRU state=h_n.
        h_n = state[0] if isinstance(state, tuple) else state  # [layers*D,B,H]
        last_layer = h_n[-self.directions:]                    # [D,B,H]
        features = last_layer.transpose(0, 1).reshape(x.size(0), -1)
        return self.head(features)                             # [B,out_dim]

[함정] 양방향 출력의 seq[:,-1,:]를 그대로 쓰면 역방향 절반은 전체 시퀀스가 아니라 마지막 토큰 하나만 읽은 상태다. 위 코드처럼 마지막 층의 h_n에서 양방향 상태를 꺼내 합친다. 가변 길이 시퀀스에 패딩을 넣었다면 h_n도 패딩의 영향을 받으므로 실제 길이 정보와 압축 시퀀스(packed sequence)를 사용한다.

위 코드에서 B=8, T=20, F=10, hidden=32, layers=2, bidirectional=True라면 입력은 [8,20,10], h_n은 [4,8,32]다. 마지막 층의 두 방향만 고르면 [2,8,32], 배치 축을 앞으로 옮기면 [8,2,32], 방향과 은닉 축을 합치면 [8,64]다. 마지막 Linear가 이 64개 요약값을 원하는 출력 크기로 바꾼다. LSTM만 (h_n,c_n)을 돌려주므로 state[0]으로 h_n을 꺼내는 분기가 있다.

내장 dropout은 순환 층과 다음 순환 층 사이에 적용된다. 2층이면 1층 출력이 2층으로 들어가는 사이에 적용되며, 마지막 층 뒤의 분류기에는 자동으로 붙지 않는다. 그래서 코드가 단층일 때 dropout을 0으로 바꾼다. 이 동작과 상태·출력의 형태는 PyTorch LSTM 문서에서 함께 확인할 수 있다.

22.6 양방향 모델의 함정

오후 3시에 오후 2시~3시의 기록으로 3시 10분을 예측한다면, 그 한 시간의 기록을 거꾸로 읽어도 아직 오지 않은 시간을 읽은 것은 아니다. 반대로 오후 2시 30분의 경고를 생성하면서 오후 2시 50분의 센서 값을 읽으면 당시 사용할 수 없던 정보를 사용한다. 중요한 것은 배열에서 오른쪽에 있는지 자체가 아니라 그 출력을 내야 하는 시각에 이미 관측된 값인지다.

입력 구간 전체가 예측 시점 이전에 관측되었다면 양방향(bidirectional) RNN으로 그 과거 구간을 앞뒤로 읽을 수 있다. 하지만 매 시점 즉시 출력하는 온라인 모델에서 미래 시점을 읽는 양방향 구조는 인과적(causal) 예측 조건을 어길 수 있다. 문제의 정의를 확인한다.

22.7 CNN1D

CNN1D는 시간상 이웃한 값들을 묶어 짧은 변화 패턴을 찾는다. RNN처럼 상태를 한 시점씩 넘기는 방식은 아니지만, 커널 내부의 각 위치에 다른 가중치를 두므로 구간 안의 순서가 사라지는 것도 아니다. PyTorch Conv1d는 센서 특성을 채널 축에, 시간을 길이 축에 둔다. 따라서 [B,T,F]를 [B,F,T]로 바꿔야 한다.

permute(0,2,1)은 각 축이 맡는 자리를 바꾸는 연산이다. 기존 x[b,t,f]의 값이 새 배열의 [b,f,t]로 가야 한다. 같은 크기로 reshape만 하면 그 대응을 보장하지 못하므로 축 교환 대신 사용할 수 없다.

PYTHON 예시
class SensorCNN1D(nn.Module):
    def __init__(self, n_features, out_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Conv1d(n_features, 64, 3, padding=1),
            nn.ReLU(),
            nn.Conv1d(64, 128, 3, padding=1),
            nn.ReLU(),
            nn.AdaptiveAvgPool1d(1),
        )
        self.head = nn.Linear(128, out_dim)

    def forward(self, x):               # [B,T,F]
        x = x.permute(0, 2, 1)          # [B,F,T]
        x = self.net(x).squeeze(-1)      # [B,128]
        return self.head(x)

CNN1D는 병렬 계산이 빠르고 국소 패턴을 잘 찾아 첫 시계열 기준 모델로 쓰기 좋다. RNN/GRU는 시간순으로 상태를 누적한다. 입력 구간이 짧고 데이터가 크면 CNN1D를 먼저 시도한다.

앞의 CNN에 입력 [8,20,10]을 넣으면 축 교환 후 [8,10,20]이 된다. 커널 3, 패딩 1, 기본 stride 1이므로 첫 합성곱은 [8,64,20], 둘째는 [8,128,20]이다. 전역 평균 풀링 후 [8,128,1], squeeze(-1) 후 [8,128]이다. 인자 없이 squeeze()를 쓰지 않은 이유는 B=1일 때도 배치 축을 보존하기 위해서다.

평균 풀링은 패턴이 나타난 정확한 위치를 잃을 수 있고, 이 코드에는 패딩 길이를 반영하는 처리도 없으므로 가변 길이 데이터를 그대로 넣어 평균내지 않는다.

22.8 가변 길이와 마스크

길이가 각각 3과 1인 구간을 한 배치로 묶으려면 짧은 구간의 뒤를 채워 직사각형 배열로 만들어야 한다. 이 채움이 패딩이다. 두 번째 구간을 [실제값,0,0]으로 만들었다고 해서 RNN이 뒤의 0 두 개를 자동으로 건너뛰지는 않는다. 입력이 0이어도 이전 상태와 편향으로 상태가 다시 계산되기 때문이다. 실제 길이 [3,1]을 알려 주는 압축 시퀀스는 그 가짜 시점을 순환 계산에서 제외한다.

PYTHON 예시
from torch.nn.utils.rnn import pack_padded_sequence

packed = pack_padded_sequence(
    padded_x, lengths.cpu(), batch_first=True, enforce_sorted=False
)
packed_out, state = model.rnn(packed)

Transformer에서는 패딩 마스크(padding mask)를 어텐션에 전달한다. 패딩 값을 0으로 만드는 것만으로 모델이 항상 무시하는 것은 아니다.

위 코드는 앞에서 정의한 모델 전체가 아니라 model.rnn에 압축 입력을 넣는다. 뒤의 상태 선택과 예측 헤드 연결은 22.5처럼 이어서 작성해야 한다. lengths는 각 구간의 실제 양의 길이이며 패딩된 T보다 클 수 없다. lengths.cpu()는 길이 텐서를 CPU에 두고, enforce_sorted=False는 사용자가 길이 내림차순으로 미리 정렬하지 않았음을 알린다. 실제 값은 앞에, 패딩은 뒤에 있는 형태를 준비한다. 단순히 가장 마지막 열을 선택하는 방법과 실제 마지막 시점의 상태를 선택하는 방법은 다르다.

  1. 먼저 무엇을 봐야 하나: batch_first, 입력 특성 수, hidden_size, 방향 수를 확인한다.

    풀이: 배치 64와 시점 20은 유지하고 각 시점의 입력 10개를 상태 32개로 바꾼다. 양방향 설정이 없으므로 방향 수는 1이다.

    정답: [64,20,32].

    왜: 각 구간의 각 시점마다 은닉 상태 하나를 출력하기 때문이다.

    헷갈리기 쉬운 부분: 마지막 상태 h_n은 단층이면 [1,64,32]이며 시점별 output과 다르다.

    한 줄 기억: 시점별 출력은 [B,T,방향 수×H]다.

  2. 먼저 무엇을 봐야 하나: PyTorch RNN 계열의 내장 dropout인지 별도로 붙인 Dropout인지 구분한다.

    풀이: 2층 구조를 입력 → 1층 → 2층 → 출력으로 그리면 내장 dropout의 위치는 1층과 2층 사이다.

    정답: 첫 층의 출력이 둘째 층으로 들어가기 전에 적용되며 마지막 층 뒤에는 적용되지 않는다.

    왜: 해당 옵션은 층 사이의 출력을 대상으로 정의되어 있다.

    헷갈리기 쉬운 부분: 단층에서는 적용할 층 사이가 없으며, 은닉 상태의 모든 연결에 임의로 30%를 지운다는 뜻도 아니다.

    한 줄 기억: 내장 dropout은 마지막 층을 제외한 층 사이에 적용한다.

  3. 먼저 무엇을 봐야 하나: 파라미터 수 비교와 실제 검증 성능 비교를 분리한다.

    풀이: GRU가 더 단순하면 학습이 빠르거나 데이터가 적을 때 유리할 수 있고, LSTM의 별도 셀 상태가 도움이 되는 문제도 있다. 같은 분할과 예산에서 평가해야 한다.

    정답: 항상 낮지 않다.

    왜: 성능은 데이터·시퀀스 길이·최적화·과적합에 함께 좌우된다.

    헷갈리기 쉬운 부분: 파라미터가 많다는 이유만으로 정확도가 높아지는 것은 아니다.

    한 줄 기억: 복잡성은 구조의 성질이고 성능은 검증으로 확인한다.

  4. 먼저 무엇을 봐야 하나: 각 출력의 예측 시각과 입력을 사용할 수 있게 되는 시각을 적는다.

    풀이: 관측이 끝난 과거 구간 전체를 앞뒤로 읽어 미래 하나를 예측하는지, 매 시점의 출력을 만들면서 그 이후 기록을 읽는지 비교한다.

    정답: 예측 시점에 아직 사용할 수 없는 미래 정보를 읽는지로 판단한다.

    왜: 누수는 정보를 읽는 방향 자체보다 실제 이용 가능 시점의 문제다.

    헷갈리기 쉬운 부분: 양방향은 무조건 누수도, 무조건 안전도 아니다.

    한 줄 기억: 그 출력을 내야 할 때 알고 있던 정보까지만 사용한다.

  5. 먼저 무엇을 봐야 하나: 현재 축의 뜻과 Conv1d가 요구하는 축의 뜻을 나란히 적는다.

    풀이: 배치 축 0은 그대로 두고 특성 축 2를 앞으로, 시간 축 1을 뒤로 보낸다.

    정답: x.permute(0,2,1)로 [B,F,T].

    왜: Conv1d는 [배치,채널,길이]를 받기 때문이다.

    헷갈리기 쉬운 부분: reshape는 같은 원소를 축의 의미에 맞게 교환하는 대체 연산이 아니다.

    한 줄 기억: RNN의 BTF를 Conv1d의 BFT로 바꾼다.

22.10 완료 기준

먼저 [2,5,3]의 가짜 입력으로 두 모델의 마지막 출력이 동일한 [2,out_dim]인지 확인한다. 다음으로 B만 1로 바꿔 배치 축이 유지되는지 보고, RNN의 층 수와 양방향 여부를 바꾸며 h_n 모양을 손으로 예측한다. 이 세 확인을 통과한 뒤 실제 데이터 학습으로 넘어가면 축 오류와 학습 성능 문제를 분리하기 쉽다.

스스로 확인하기

  1. batch_first=True, B=8,T=10,F=4,H=6인 한 층 단방향 GRU의 시점별 출력과 h_n의 형태는?
    풀이에 필요한 이론

    입력·시점별 출력·최종 상태는 축 구성이 다르다

  2. LSTM에서 c_old=1,f=0.5,i=0.2,g=0.5이면 c_new는 얼마인가?
    풀이에 필요한 이론

    LSTM의 세 게이트와 두 상태를 구분한다

  3. 전체가 이미 관측된 과거 20시점으로 다음 날 하나를 예측한다. 양방향 RNN이 이름만으로 무조건 미래 누수인가?
    풀이에 필요한 이론

    패딩·양방향 구조·Conv1d에서 미래 정보를 사용하지 않는 조건

스스로 푼 뒤 정답과 이유 펼치기

  1. 먼저 볼 조건: batch_first=True, 단층, 단방향, B=8,T=10,F=4,H=6을 각각 적는다.

    • 단계 풀이: 시점마다 여섯 은닉값을 반환하므로 시점별 출력은 [8,10,6]이다. 최종 상태는 층×방향=1개에 표본 8개, 은닉 6개를 넣는다.
    • 정답: 시점별 출력은 [8,10,6], h_n은 [1,8,6]이다. batch_first가 상태 텐서의 축 순서까지 바꾸지 않는다는 점을 확인한다.
    • 왜: 전체 시점 출력과 층별 최종 상태는 서로 다른 정보를 담는 반환값이다.
    • 헷갈리기 쉬운 부분: batch_first가 h_n의 배치 축까지 맨 앞으로 옮긴다고 읽지 않는다.
    • 한 줄 기억: 입출력은 B 먼저여도 h_n은 층×방향 먼저다.

  2. 먼저 볼 조건: 셀 상태 c를 묻고 출력 게이트 o나 은닉 상태 h는 묻지 않는다.

    • 단계 풀이: 이전 기억 1에 f=0.5를 곱해 0.5를 남긴다. 새 후보 0.5에 i=0.2를 곱해 0.1을 기록한다. 둘을 더한다.
    • 정답: 0.5×1+0.2×0.5=0.6이다. 이전 기억의 일부와 새 후보값의 일부를 더한다. 은닉 상태를 구하려면 출력 게이트 값이 추가로 필요하다.
    • 왜: 셀 상태는 남긴 과거와 기록할 새 후보의 합이다.
    • 헷갈리기 쉬운 부분: 0.6을 h라고 부르지 않는다. h에는 tanh와 출력 게이트가 추가로 필요하다.
    • 한 줄 기억: c는 남긴 기억+새 기록, h는 별도 출력이다.

  3. 먼저 볼 조건: 예측 하나를 낼 시점에 과거 스무 관측이 모두 알려졌는지 확인한다.

    • 단계 풀이: 정방향도 역방향도 이미 주어진 스무 관측만 읽는다. 실제 예측 시점 이후의 새로운 관측을 추가로 읽는지 검사한다.
    • 정답: 무조건은 아니다. 예측 기준 시점 이전에 모두 관측된 구간을 양방향으로 읽는다면 이용 가능한 정보만 사용하는 것이다. 매 시점 즉시 내는 출력에서는 해당 예측 기준 시점 이후를 읽지 않는지 별도 검사한다.
    • 왜: 읽는 방향이 반대라는 사실과 미래 정보를 얻었다는 사실은 다르다.
    • 헷갈리기 쉬운 부분: 매 시점 즉시 출력을 내는 과제에 같은 결론을 무조건 적용하지 않는다.
    • 한 줄 기억: 누수 여부는 방향 이름보다 정보 공개 시점으로 판단한다.
