### 치트시트를 코드에 연결하는 공통 순서

1. [문제 유형 결정표](/cheatsheet.html#60)를 열고 문제의 입력 형태를 찾습니다. 표면적인 ‘자동차’라는 소재보다 표·이미지·시계열인지가 중요합니다.
2. [유형별 가이드](/playbook/)에서 해당 유형을 엽니다. 문제별 매뉴얼에는 정확한 번호와 함수명이 적혀 있습니다.
3. Process는 비슷한 함수를 가져오되 **이 문제의 명세가 우선**입니다. 예를 들어 이미지의 중앙을 자르는 것과 왼쪽 위를 자르는 것은 같은 답이 아닙니다.
4. Problem은 `import hdat_templates as h` 후 전처리, 모델, 학습 루프, 제출 변환의 네 부분을 연결합니다. `h.MLP`를 복사할 필요 없이 `h.MLP(입력열수, 출력개수)`처럼 호출합니다.
5. 아래 공통 실행 블록을 쓰려면 앞에서 `Xtr`, `Xva`, `Xte`, `ytr`, `yva`, `model`, `task`, `score_fn`, `maximize`를 모두 정의해야 합니다. 이 이름들은 자동으로 생기지 않습니다.

```python
import numpy as np
import hdat_templates as h

# 전처리와 모델 정의가 끝난 후 solve() 내부에 넣는 공통 블록입니다.
tr = h.make_tensor_loader(Xtr, ytr, task, batch_size=32, shuffle=True)
va = h.make_tensor_loader(Xva, yva, task, batch_size=64, shuffle=False)
te = h.make_tensor_loader(Xte, task=task, batch_size=64, shuffle=False)
model, history = h.train_torch_model(
    model, tr, va, task, epochs=15, patience=5, lr=0.003,
    device="cpu", score_fn=score_fn, maximize=maximize,
)
pred = h.predict_torch(model, te, task, device="cpu",
                       return_proba=case in {"B06", "B07"})
# 마지막에 문제별 라벨 복원·역변환·error 계산 후 return pred
```

`task`는 손실함수와 정답 자료형을 정합니다. `score_fn`은 각 에포크(epoch)에서 어떤 모델을 남길지 결정합니다. 분류에서는 손실을 줄이면서 Macro-F1 또는 AUC가 가장 높은 모델을 고를 수 있습니다. 학습에 쓰는 손실과 모델 선택 지표는 목적이 다릅니다. 학습 반복문은 가장 좋은 에포크의 가중치를 돌려주므로 마지막 에포크의 모델로 임의 교체하지 마세요.

## P01. 선택 센서 열만 Min-Max 변환

Process · 쉬움 · 권장 8분. 표 전체를 바꾸지 않고 지정된 열만 정확하게 바꾸는 문제입니다.

### 문제와 입출력 조건

`scale_sensor_columns(frame, columns)`를 구현하세요. `frame`은 열 이름이 유일한 pandas DataFrame이고, `columns`는 중복 없는 열 이름 리스트입니다. 선택한 열은 수치형이며 NaN은 허용하지만 Inf는 입력으로 주어지지 않습니다. 선택한 각 열에서 결측값을 제외하고 최솟값·최댓값을 구해 `(x-min)/(max-min)`을 계산하세요.

상수 열의 **유효값만 0.0으로 바꾸고**, 전부 NaN인 열은 NaN을 유지합니다. 선택한 열의 결과 자료형은 float64입니다. 선택하지 않은 열의 값·자료형, 행·열 순서, 중복될 수 있는 인덱스는 유지합니다. 원본은 바꾸지 않고 새 DataFrame을 반환합니다. 빈 DataFrame과 빈 선택 목록도 허용합니다. 없는 열을 선택하면 KeyError, 선택 목록이 중복되면 ValueError를 발생시킵니다.

```python
import numpy as np
import pandas as pd
frame = pd.DataFrame({"sensor": [4., 10., 7., np.nan], "fixed": [8, 8, 8, 8],
                      "code": ["A", "B", "C", "D"]}, index=[9, 9, 2, 4])
# sensor -> [0.0, 1.0, 0.5, NaN], fixed -> [0.0]*4
# code와 index [9,9,2,4]는 그대로
```

### 힌트

`frame.copy(deep=True)`를 먼저 만드세요. 열마다 `s.min()`, `s.max()`를 구합니다. NaN을 0으로 채우라는 명세가 아니므로 `fillna(0)`는 여기서 오답입니다.

## P02. 중앙값과 IQR로 센서 안정화

Process · 쉬움–보통 · 권장 8분. P01의 기본 구조에서 통계량과 분모가 0일 때의 처리만 정확히 바꾸는 연습입니다.

### 문제와 입출력 조건

`robust_sensor_columns(frame, columns)`를 구현하세요. 입력 보존·출력 자료형·NaN·빈 입력·없는 열·중복 열의 처리 규칙은 P01과 같습니다. 각 열에서 `(x - median) / IQR`을 계산합니다. `IQR = Q(0.75)-Q(0.25)`이며 분위수를 구할 때 **선형 보간**(linear)을 사용합니다.

IQR이 정확히 0이면 그 열의 유효값은 모두 0.0으로 바꿉니다. 이는 이 문제에서 명시한 예외 처리입니다. 모든 특수 입력에서 일반 라이브러리의 RobustScaler와 똑같이 동작한다고 가정하지 마세요.

```text
입력 [0, 2, 4, 6]: median=3, Q1=1.5, Q3=4.5, IQR=3
반환 [-1, -1/3, 1/3, 1]
입력 [0,0,0,0,100]: IQR=0 → [0,0,0,0,0]
```

### 힌트

P01에서 복사본 생성·선택 열 순회는 그대로입니다. 최솟값을 중앙값으로, 범위를 IQR로 바꾸세요. ‘이상치가 있으니 100을 그대로 둔다’는 직관보다 명세가 우선입니다.

### 치트시트 수정 매뉴얼

1. [선택 열 변환 가이드](/playbook/01/)의 함수의 입출력 조건을 연 뒤 P01 구현을 별도 함수로 복사합니다.
2. `s = frame[col].astype("float64")`는 유지합니다. `s.median()`과 `s.quantile(.75, interpolation="linear")`를 사용합니다.
3. 상수 판정 `max == min`을 `iqr == 0`으로 바꿉니다. 두 조건은 같지 않습니다. 예제의 100이 바로 차이를 드러냅니다.
4. 나눗셈 결과를 원본에 대입하지 말고 `out[col]`에 넣은 뒤 `return out`으로 반환합니다.
5. P01의 검사만 통과했다고 끝내지 말고 분위수 보간 예제와 IQR=0 비상수 열을 검사하세요.

```bash
python check_process.py --case P02 --file process_starter.py
```

### 해설과 재도전

IQR은 가운데 50%에 해당하는 값의 범위입니다. 평균·표준편차보다 일부 극단값의 영향을 적게 받을 수 있지만, IQR=0인 데이터를 어떻게 처리할지는 따로 정해야 합니다. 이 문제에서는 명세대로 0을 반환합니다. 실제 모델 전처리에서는 훈련 데이터의 중앙값과 IQR을 보관해 검증·테스트 데이터에 재사용해야 합니다.

참고 구현의 `_selected`, `robust_sensor_columns`를 확인하세요. 재도전: 선형 보간 대신 최근접 보간(nearest)을 썼을 때 `[0,2,4,6]`의 결과가 왜 달라지는지 계산하세요. 수정 후에도 선택하지 않은 문자열 열의 자료형이 바뀌지 않았는지 확인합니다.

## P03. 설비별 과거 두 행의 평균

Process · 보통 · 권장 12분. 정렬·그룹·현재값 제외·원래 순서 복원의 네 가지를 함께 다룹니다.

### 문제와 입출력 조건

`add_prior_average(frame, group_col, time_col, value_col, window=2)`를 구현하세요. 그룹 열은 결측 없는 문자열, 시간 열은 결측 없는 정수이고, 값 열은 수치형이며 NaN을 허용합니다. 열 이름은 유일하고 원본 인덱스는 중복될 수 있습니다.

그룹별로 시간 오름차순으로 정렬하되, 시간이 같으면 원래 행 위치가 앞선 것을 먼저 둡니다. 각 행에서 **현재 행을 제외한 직전 window개의 관측 행**의 평균을 계산합니다. NaN은 그 범위의 평균 계산에서 제외하며, 사용할 유효값이 없으면 NaN을 반환합니다. 유효값 window개를 찾을 때까지 더 과거로 이동하라는 뜻은 아닙니다.

원본은 변경하지 않습니다. 기존 값·자료형·인덱스·순서를 모두 유지한 표를 반환하고, 마지막에 float64형 `<value_col>_prior_mean` 열을 추가합니다. 그 열이 이미 있으면 ValueError, 인수로 지정한 열이 없으면 KeyError를 발생시킵니다. window는 bool이 아닌 양의 정수여야 하며, 그렇지 않으면 ValueError를 발생시킵니다. 빈 표도 허용합니다.

```text
원래 행: group [A, B, A, A, B]
          time [3, 2, 1, 2, 1]
         value [30,100,10,20,80]
반환 새 열: [15, 80, NaN, 10, NaN]
```

### 힌트

그룹별로 `shift(1)`을 먼저 적용한 뒤 `rolling(window, min_periods=1).mean()`을 계산합니다. 원본 인덱스가 중복되므로 인덱스로 원래 순서를 복원하려 하지 말고, 0부터 시작하는 행 위치를 별도로 기록하세요.

### 치트시트 수정 매뉴얼

1. [그룹별 시차·이동 통계](/playbook/02/)을 엽니다. `group_col`, `time_col`, `value_col`은 문자열 인수로 받고 실제 열 이름을 하드코딩하지 마세요.

3. 그룹, 시간, 행 위치의 세 기준으로 정렬합니다. 이어서 `groupby(...).transform(...)` 안에서 시차 이동과 이동 평균 계산을 함께 수행합니다.
4. 결과를 길이 N의 NaN 배열에 `result[정렬된 원래위치] = 계산값`으로 배치합니다. 마지막에 원본 복사본의 새 열로 넣습니다.
5. A그룹의 첫 행에 B그룹의 값이 섞이지 않는지, 현재 행을 99999로 바꿔도 그 행의 과거 평균은 그대로인지 검사합니다.


### 해설과 재도전

현재값을 제외하지 않으면 ‘현재값으로 현재를 예측’하는 누수가 생깁니다. 그룹 구분 없이 이동 평균을 계산하면 다른 설비의 기록이 섞입니다. 정렬 결과 그대로 반환하면 값 계산이 맞아도 예측값과 제출 행의 대응이 틀립니다.

## P04. 로짓이 커도 안정적인 교차엔트로피

Process · 보통 · 권장 10분. PyTorch 손실함수를 호출하지 않고 NumPy로 수식을 구현합니다.

### 문제와 입출력 조건

`mean_logit_loss(logits, labels)`를 구현하세요. logits는 유한한 실수 `(N,C)` 배열이며 N≥1, C≥1입니다. labels는 정수형 `(N,)` 배열이고 값의 범위는 0부터 C-1입니다. 각 행에서 소프트맥스의 정답 클래스 확률에 음의 로그를 취한 뒤 평균하여 Python `float` 하나를 반환합니다. 내부 연산은 float64로 하고 입력은 바꾸지 않습니다.

형태가 잘못되었거나 입력이 비어 있으면 ValueError를 발생시킵니다. 실수형·bool형 labels, 범위 밖 라벨, NaN/Inf가 있는 logits도 ValueError입니다. 특히 `(N,1)` 형태의 labels를 자동으로 펼쳐 받아들이지 않습니다.

```text
logits=[[0,0],[log(3),0]], labels=[0,1]
정답=(log(2)+log(4))/2 ≈ 1.03972077
logits가 모두 1000인 3클래스 → log(3), overflow 없어야 함
C=1, labels가 모두 0 → 0.0
```

### 힌트

로짓에 같은 수를 더하거나 빼도 소프트맥스 확률은 같습니다. 각 행의 최댓값을 빼고 지수를 계산하세요. 확률을 만든 뒤 `log(0)`을 피하려고 임의의 작은 값 엡실론(epsilon)을 더하기보다 로짓에서 직접 로그-합-지수(log-sum-exp)를 계산하는 편이 정확합니다.

### 치트시트 수정 매뉴얼

1. [NumPy 수치 함수](/playbook/03/)를 엽니다. 평균 MSE 예시라면 반복 뼈대만 참고하고 계산식은 반드시 바꿉니다.
2. 입력 조건을 먼저 확인합니다. labels를 무조건 `astype(int)` 하면 0.9 같은 잘못된 입력도 오류 없이 통과하므로 먼저 정수 자료형인지 검사합니다.
3. `z = x.astype(np.float64) - x.max(axis=1, keepdims=True)`를 만듭니다. keepdims가 있어야 행별 최댓값이 같은 행에 적용됩니다.
4. `np.log(np.exp(z).sum(axis=1)) - z[np.arange(N), y]`가 표본별 손실입니다. 평균을 구해 `float(...)`로 반환합니다.
5. [형태·손실함수 표](/cheatsheet.html#2-pytorch-shapeloss)로 실제 모델 학습에서는 CrossEntropyLoss에 소프트맥스를 적용하기 전 로짓을 입력하는 이유까지 연결하세요.

```bash
python check_process.py --case P04 --file process_starter.py
```

### 해설과 재도전

최댓값을 빼면 지수함수의 입력 최댓값이 0이므로 큰 양수의 지수 계산에서 발생하는 오버플로(overflow)를 막습니다. 로그-합-지수에서 정답 로짓을 빼므로 공통으로 뺀 값도 상쇄됩니다. 반면 확률에 엡실론을 더하면 원래 수식의 값이 달라질 수 있습니다.

참고 함수 `mean_logit_loss`와 비교하고 로짓에 10000을 더한 결과가 같은지 검사하세요. 재도전: labels의 형태가 `(2,1)`인 경우, -1인 경우, C=1인 경우를 직접 실행하고 명세에 맞는 성공/실패를 예측하세요.

## P06. 명세 그대로 구현하는 작은 MLP

Process · 보통 · 권장 8분. 좋은 모델을 설계하는 문제가 아니라 정확한 구조를 구현하는 문제입니다.

### 문제와 입출력 조건

`SensorMLP()`라는 `nn.Module`을 작성하세요. `self.network`는 다음 순서의 `nn.Sequential`입니다. 두 Linear의 편향(bias) 설정은 모두 True이고 BatchNorm은 PyTorch 기본 인수입니다.

```text
입력: float32 (B,12), 출력: raw logits (B,4)
train 모드 B≥2, eval 모드 B≥1. 추가 Softmax/Sigmoid 없음.
```

### 힌트

## P07. 해상도가 달라도 동작하는 CNN

Process · 보통 · 권장 10분. 합성곱의 출력 크기 계산과 펼치기 연산에서 배치 축을 유지하는 방법을 확인합니다.

### 문제와 입출력 조건

`SurfaceCNN()`을 구현하세요. float32 입력의 형태는 `(B,1,H,W)`이고 H/W≥4이며, 변환 전 로짓 `(B,2)`를 반환합니다. `self.features`는 아래 일곱 층으로 구성한 Sequential이고, `self.head`는 `Linear(10,2,bias=True)`입니다.

```text

BatchNorm2d(6) [기본 인수]
ReLU
MaxPool2d(kernel_size=2,stride=2)
Conv2d(6,10,kernel_size=3,stride=2,padding=1,bias=True)
ReLU
AdaptiveAvgPool2d(1)
```

특징 추출 결과를 `flatten(1)`로 펼친 뒤 헤드에 넣습니다. 활성함수를 추가하지 않으며 총 학습 파라미터 수는 638개입니다. 훈련·평가 모드 전환과 역전파가 가능해야 하고 원본 입력은 바꾸지 않습니다. 입력 `(2,1,13,17)`의 최종 출력 형태는 `(2,2)`입니다.

## P08. 양방향 GRU의 마지막 상태 결합

### 문제와 입출력 조건

`TripGRU(n_features, hidden_size, n_outputs)`를 구현하세요. 세 인수는 bool이 아닌 양의 정수이며 아니면 ValueError입니다. `self.gru`는 GRU, 2층, batch_first=True, bidirectional=True, dropout=0.1입니다. 편향 등 나머지 인수는 기본값입니다.

## B02. 양수 수요 예측 · RMSLE

Problem · 기본 · 권장 40분. 로그 변환한 정답으로 학습하되 제출값은 원래 단위로 되돌리는 문제입니다.

### 문제와 입출력 조건

합성 운행 조건의 수치 6열과 범주 1열로 비음수 수요를 예측하세요. 데이터 구조와 행 수는 B01과 같습니다. 다만 y_train/y_valid는 비음수 float32 `(N,1)`이며 연속값도 가능합니다. 정수로 반올림하라는 지시는 없습니다.

제출값은 `(97,1)` 형태이며 원래 단위의 비음수 실수입니다. 지표는 `sqrt(mean((log1p(y)-log1p(pred))**2))`이며 작을수록 좋습니다. 표형 입력의 결측값은 훈련 통계로 처리하고, 정답이나 테스트 데이터를 포함해 전처리를 학습하지 않습니다.

### 힌트

학습용 y를 log1p로 바꾸면 값의 크기 차이가 줄어듭니다. 로그 단위의 모델 출력을 그대로 제출하면 단위가 틀립니다. 반대 함수는 exp가 아닌 expm1입니다.

### 치트시트 수정 매뉴얼

1. [표형 회귀·RMSLE](/playbook/06/)와 [RMSLE 코드](/cheatsheet.html#7-rmsle)를 엽니다. B01에서 데이터 전처리 부분만 가져오고 라벨 인코딩·argmax는 제거합니다.
2. `ytr=np.log1p(data["y_train"])`, 검증 정답도 동일하게 변환합니다. `(N,1)`을 유지합니다.
3. `h.MLP(Xtr.shape[1],1,hidden=(32,16),dropout=0)`, `task="regression"`, `maximize=False`로 설정합니다. 공통 학습 반복문은 MSELoss를 사용합니다.
4. 콜백의 truth는 이미 로그 단위입니다. 예측에 expm1 역변환 → 0 이상으로 제한 → log1p 변환을 적용한 뒤 비교하면 실제 제출값과 같은 기준의 RMSLE를 얻습니다.

```python
def score_fn(truth, raw):
    restored = np.clip(np.expm1(raw), 0, None)
    return float(np.sqrt(np.mean((truth - np.log1p(restored)) ** 2)))
# 공통 RUN 이후
pred = np.clip(np.expm1(pred), 0, None)
return pred  # shape (N,1), rounding/argmax 없음
```

5. [제출 검사](/playbook/13/)를 보고 `--case B02`로 실행합니다. `(97,)`이면 1열이 사라진 원인을 찾으세요. 모든 출력을 강제로 reshape해서 원인을 숨기지 않습니다.

### 해설과 재도전

참고 풀이의 `CASE B02`와 제출 어댑터를 확인하세요. ‘학습 손실을 계산하는 단위’와 ‘저장하는 단위’를 종이에 적는 습관이 중요합니다. 예측값을 0 이상으로 제한하는 것은 이 문제의 비음수 조건에 따른 예측 정책이지 모든 회귀에서 쓰는 만능 규칙이 아닙니다.

훈련 정답에 log1p를 적용한 뒤 그 평균을 모든 검증 행의 예측으로 사용하고 expm1로 복원해 기준 성능을 계산합니다. MLP가 이 기준 예측보다 좋은지 확인하세요. 재도전: 원래 y에 MSE를 적용해 학습한 모델과 log1p로 학습한 모델을 **같은 검증 RMSLE**로 비교합니다. 서로 다른 지표로 평가하면 결과를 직접 비교할 수 없습니다.

자주 나는 오류는 정답을 StandardScaler와 로그로 두 번 변환하고 한 번만 역변환하는 것, exp를 사용해 1이 더해지는 것, 원래 단위의 정답 대신 로그값을 저장하는 것, 정답 `(N,1)`에서 예측 `(N,)`을 빼 NxN 브로드캐스팅이 일어나는 것입니다.

## B03. 센서 시계열 · 6시점 뒤 3개 값 예측

Problem · 실전 핵심 흐름 · 권장 80–100분. 원본 시계열에서 입력 구간을 만들고 미래 정답의 대응·시간순 분할·원래 단위의 평가까지 수행합니다.

### 문제와 입출력 조건

`data/B03.npz`의 `raw_X`는 시간순으로 정렬된 `(1400,6)` 형태의 실수 센서 배열입니다. 입력 끝 위치 e에서 **e-11부터 e까지 12행**을 사용해 **e+6인 한 시점의 정답값 3개**를 예측합니다. 미래 6개 시점 전체를 예측하는 문제가 아닙니다. 예측 기준 시점(rolling origin)을 순차적으로 옮기며, 각 시점에서는 그때까지 관측된 값만 사용할 수 있습니다.

`ends_train`은 11…833의 823개, `ends_valid`는 840…1113의 274개, `ends_test`는 1120…1393의 274개 위치를 담습니다. 이 중 테스트 위치는 순서가 섞여 있습니다. y_train/y_valid는 각각 입력 끝 위치 목록과 같은 순서로 대응하는 `(N,3)` 형태의 원래 단위 정답입니다. 제공된 분할을 유지하세요. raw_X의 미래 부분을 미리 읽어 특성으로 쓰면 안 됩니다.

테스트 입력 끝 위치 목록의 순서대로 `(274,3)` 형태의 실수 예측을 원래 단위로 반환합니다. 지표는 **전체 N×3 원소의 MSE**입니다. 열별 MSE의 합, 표준화된 MSE, RMSE는 이 문제의 지표가 아닙니다. 입력에 쓰는 과거 관측은 분할 시점 이전까지 포함해도 되지만, 학습 정답의 시점은 다음 분할의 첫 예측 기준 시점보다 앞서야 합니다.

```text
e=11 → 입력 raw_X[0:12], 정답 시점 17
e=12 → 입력 raw_X[1:13], 정답 시점 18
train 마지막 정답 시점 833+6=839 < valid 첫 origin 840
valid 마지막 정답 시점 1113+6=1119 < test 첫 origin 1120
```

### 힌트

먼저 모델 없이 입력 구간 2개를 만들고 위 인덱스와 일치하는지 확인하세요. 구간을 만든 뒤 무작위로 분할하면 인접 관측과 미래 정답이 섞입니다. 이 템플릿의 CNN1D는 `(N,T,F)` 형태의 입력을 받습니다.

### 치트시트 수정 매뉴얼

1. [원본 시계열 가이드](/playbook/10/) → [이미 만든 입력 구간](/playbook/09/) → [다중 출력 회귀](/playbook/06/) 순서로 엽니다.
2. `L=12`, `H=6`, 출력 수 3을 메모합니다. 공통 코드의 변수 LOOKBACK/HORIZON이 있다면 이 값으로 바꾸세요. 입력 끝 위치와 정답 위치를 혼동하지 않습니다.

```python
raw = data["raw_X"]
L, H = 12, 6
def window(ends):
    return np.stack([raw[e-L+1:e+1] for e in ends]).astype(np.float32)
Xtr, Xva, Xte = [window(data[f"ends_{s}"]) for s in ("train", "valid", "test")]
assert (data["ends_train"] + H).max() < data["ends_valid"].min()
assert (data["ends_valid"] + H).max() < data["ends_test"].min()
```

3. [시퀀스 스케일링](/cheatsheet.html#sequence-scaling)의 `h.fit_scale_3d(Xtr)`로 훈련 특성 통계를 구하고 훈련·검증·테스트에 같은 `h.transform_scale_3d`를 적용합니다. 겹치는 훈련 구간의 값이 반복 반영되는 것은 이 참고 구현의 정규화 정책이며 미래 데이터는 사용하지 않습니다.
4. 정답용으로는 `StandardScaler().fit(y_train)`을 따로 보관합니다. 훈련·검증 정답을 변환한 `(N,3)` 형태의 float32로 학습합니다. 입력용 스케일러와 정답용 스케일러를 구분해야 합니다.
5. [CNN1D](/cheatsheet.html#cnn1d-window-sequence)의 `h.CNN1D(6,3,channels=(16,32),dropout=0)`, task를 regression으로 시작합니다. 템플릿 내부에서 채널 축으로 재배열하므로 외부에서 다시 `(N,F,T)`로 바꾸지 않습니다.
6. 평가 콜백에서 truth와 raw를 **둘 다 target_scaler.inverse_transform**한 다음 전체 원소 MSE를 계산하고 maximize=False로 둡니다. 세 정답 항목의 크기가 달라 표준화 MSE와 원 단위 MSE의 모델 순위는 달라질 수 있습니다.
7. 공통 실행 블록의 pred를 역변환하고 float32로 반환합니다. 테스트 입력 끝 위치를 정렬하거나 정답 축을 평균해서 없애지 않습니다.
8. `--case B03`으로 저장 후 다시 읽어 검사한 뒤 검증용 기준 예측과 비교하고 최종 자가채점합니다.

### 해설과 재도전

참고 풀이의 `CASE B03`은 입력 구간 생성, 두 분할 지점의 시간 조건 검사, 입력·정답 스케일링, 원래 단위로 평가하는 콜백을 한 블록에 보여 줍니다. 정답은 제공된 `y_*`를 사용하며 raw_X의 미래 행에서 직접 답을 만드는 코드가 아닙니다.

먼저 훈련 정답 y의 열별 평균을 모든 검증 행에 반복한 `(N,3)` 형태의 기준 예측을 만드세요. 마지막 입력 X의 첫 세 열을 그대로 y로 반환하는 것은 올바른 직전 값 유지(persistence) 예측이 아닙니다. 이 문제에서는 입력 센서와 정답의 단위·의미가 서로 다르기 때문입니다.

재도전: 입력 구간 전체의 평균 특성을 사용하는 MLP와 CNN1D를 같은 분할과 원래 단위의 MSE로 비교합니다. LSTM/GRU로 바꿀 때도 입력 `(N,12,6)`과 출력 `(N,3)` 형태는 유지합니다. 예측 간격을 바꾸려면 데이터와 정답도 다시 정의해야 하므로 H 숫자만 바꾸고 기존 y를 사용하면 틀립니다.

**실수 복구:** 점수가 비정상적으로 좋으면 미래 행·테스트 통계 사용과 누수부터 확인합니다. 형태 경고 없이 손실이 계산되어도 `(N,1,3)`과 `(N,3)` 사이에 브로드캐스팅이 일어날 수 있으므로 assert로 형태가 정확히 같은지 검사하세요. 테스트 순서가 섞여 있는 것은 의도한 함정입니다.

## B05. 정상 데이터만으로 이상 점수 만들기

Problem · 응용 · 권장 50분. Autoencoder의 재구성 값과 최종 이상 점수가 다른 것을 익힙니다.

### 문제와 입출력 조건

센서 특성 6개로 구성된 훈련 `(600,6)`과 검증 `(120,6)`에는 정상 상태만 있고, 테스트 `(127,6)`에는 정상과 이상이 섞여 있습니다. 모두 float32이며 결측값은 없습니다. 훈련·검증 데이터에는 y가 없습니다. 작은 잠재 공간(latent space)으로 압축한 뒤 복원하는 PyTorch 오토인코더(Autoencoder)를 학습하세요.

표준화된 테스트 표본마다 **6개 특성의 평균 제곱 재구성 오차**를 반환합니다. 형태는 `(127,)`이며 비음수 실수입니다. 값이 클수록 이상이라고 정의합니다. 자가채점 지표는 이상=1을 양성으로 한 ROC-AUC입니다. 확률이나 임계값을 적용한 0/1 라벨을 요구하지 않습니다.

### 힌트

오토인코더의 학습 정답은 X 자신입니다. 정상 데이터를 잘 복원하는 작은 모델을 만든 뒤, 테스트 입력과 복원값의 차이를 특성 축에서 평균합니다. 정상만 있는 검증 데이터로는 ROC-AUC를 계산할 수 없습니다.

### 치트시트 수정 매뉴얼

1. [정상 데이터만 사용하는 AE 가이드](/playbook/12/)와 [Autoencoder 이상 탐지](/cheatsheet.html#14-autoencoder)를 엽니다.
2. `StandardScaler().fit(data["X_train"])` 후 훈련·검증·테스트를 변환합니다. 표준화된 공간의 오차를 제출해야 하므로 뒤에서 역변환하지 않습니다.
3. `ytr=Xtr.copy()`, `yva=Xva.copy()`, task를 regression으로 둡니다. 라벨이 없다고 모두 0 정답을 만들어 주면 복원을 배우지 못합니다.
4. `h.Autoencoder(6,latent_dim=2,hidden_dim=16)`을 사용합니다. 정상 검증 데이터의 복원 MSE가 가장 작은 모델을 남기고 조기 종료합니다. maximize=False이며 여기의 평가 콜백은 AUC가 아니라 MSE입니다.
5. 공통 실행 블록의 pred는 아직 `(N,6)` 형태의 재구성 값입니다. 제출할 오차로 바꾸는 마지막 변환이 필요합니다.

```python
pred = np.mean((Xte - pred) ** 2, axis=1)
return pred  # (127,), 큰 값=이상. threshold와 sigmoid 없음
```

6. `--case B05`로 형식을 확인합니다. 테스트 정답은 마지막 자가채점에서만 열립니다. 모든 점수가 같으면 AUC가 보통 0.5이며 정상과 이상을 구분하지 못하는 상태입니다.

### 해설과 재도전

참고 풀이 `CASE B05`는 정상 검증 데이터의 복원 오차로만 모델을 고릅니다. 정상과 이상이 섞인 검증 라벨이 없으므로 AUC를 최적화하거나 ‘검증 AUC가 가장 높은 모델’을 골랐다고 말할 수 없습니다. 모델 용량을 지나치게 키우면 이상 입력도 잘 복원할 수 있습니다.

재도전: latent_dim=1/2/4 중 두 개만 선택해 정상 검증 MSE와 이상 점수의 분포를 비교합니다. 정상 복원 MSE가 낮아도 이상탐지 AUC가 반드시 높지는 않은 이유를 설명하세요. 임계값을 요구하는 별도 문제라면 정상 검증 데이터의 분위수 등으로 먼저 정한 뒤 테스트에 적용합니다. **이 B05에서는 임계값을 적용하지 않은 점수를 제출합니다.**

자주 나는 오류는 테스트를 훈련에 합치는 것, `y_train` 키를 찾다가 중단하는 것, 오차를 배치 축 axis=0으로 평균하는 것, 작은 오차를 이상이라고 보고 부호를 뒤집는 것, 임의의 sigmoid를 적용해 지정된 재구성 오차를 바꾸는 것입니다.

## B06. 고장 확률 · 양성 라벨이 2인 이진분류

Problem · 기본 · 권장 40분. 숫자가 큰 클래스가 양성이라는 무의식적 가정을 깨는 문제입니다.

### 문제와 입출력 조건

B01과 표형 구조와 행 수가 같은 합성 데이터입니다. y의 원래 값은 **고장=2, 정상=5**입니다. 요구하는 것은 고장일 확률 `P(y=2)`입니다. 훈련·검증에는 두 클래스가 모두 있으며, 입력의 결측값과 테스트의 미지 범주 D도 있습니다.

`(97,1)` 형태의 0~1 범위 실수 확률을 반환합니다. 지표는 고장=2를 양성으로 계산한 ROC-AUC이며 클수록 좋습니다. 2/5 라벨, 0/1 분류 결과, 정상일 확률, 두 열짜리 확률은 이 문제에서 요구하는 출력이 아닙니다.

### 힌트

정답을 `(y==2).astype(float)`로 바꾸세요. `LabelEncoder` 기본 정렬 결과만 믿으면 2가 0에 대응하므로 양성 의미가 뒤집힐 수 있습니다.

### 치트시트 수정 매뉴얼

1. [이진분류·확률 제출](/playbook/07/)와 [형태·손실함수 표](/cheatsheet.html#2-pytorch-shapeloss)를 엽니다. 입력 전처리에는 훈련 데이터로만 학습하는 B01의 함수를 재사용합니다.
2. `ytr=(data["y_train"]==2).astype(np.float32).reshape(-1,1)`로 만들고 검증 정답에도 동일하게 적용합니다.
3. `h.MLP(Xtr.shape[1],1,hidden=(32,16),dropout=0)`, task를 binary로 둡니다. 학습 손실함수는 BCEWithLogitsLoss이므로 모델 끝에 Sigmoid를 붙이지 않습니다.
4. AUC 평가 콜백에서 변환 전 로짓에 sigmoid를 적용한 값과 0/1 정답 truth를 비교합니다. `maximize=True`입니다. AUC 계산을 위해 임계값 .5로 0/1을 결정하면 순위 정보를 잃습니다.

```python
import torch
from sklearn.metrics import roc_auc_score
def score_fn(truth, raw):
    probability = torch.sigmoid(torch.from_numpy(raw)).numpy()
    return roc_auc_score(truth.reshape(-1), probability.reshape(-1))
```

5. 공통 실행 블록의 `return_proba=True`는 추론할 때 sigmoid를 한 번 적용합니다. 그 결과에 다시 sigmoid를 적용하거나 라벨로 복원하지 말고 그대로 반환합니다.
6. `--case B06`으로 검사합니다. 평균 확률이 0.5 근처인지만 보지 말고 검증 데이터의 양성·음성 점수 분포와 AUC의 방향을 확인하세요.

### 해설과 재도전

참고 풀이 `CASE B06`와 `predict_torch`에서 이진분류 확률을 만드는 부분을 함께 확인하세요. ‘BCE 손실함수에는 로짓, 제출에는 확률’이 핵심입니다. 이 문제는 확률 보정 성능이 아니라 AUC로 순위를 평가하지만, 반환값은 0~1 확률이어야 합니다.

항상 같은 확률을 예측하면 AUC는 0.5입니다. 재도전: 검증 데이터에서 p와 1-p의 AUC를 비교해 양성 방향을 확인합니다. p의 성능이 좋지 않다고 테스트 점수를 보고 뒤집지는 마세요. 어느 쪽을 양성으로 볼지는 문제의 라벨 정의에 따라 정해야 합니다.

자주 나는 오류는 5를 양성으로 학습하는 것, BCE 정답에 정수형 long을 쓰는 것, 모델 안팎에서 sigmoid를 두 번 적용하는 것, return_proba=False로 임계값을 적용하는 것, `(N,)` 형태로 저장하는 것입니다.

## B07. 여러 상태를 동시에 예측하는 다중 라벨 분류

Problem · 기본–응용 · 권장 45분. 세 클래스 중 하나를 고르는 문제와 세 개 독립 상태를 예측하는 문제를 구분합니다.

### 문제와 입출력 조건

B01과 수치 6열·범주 1열·행 수가 같습니다. y_train/y_valid는 float32 `(N,3)` 형태이며 각 값은 상태 여부를 나타내는 0/1입니다. 열 순서는 과열, 진동, 과부하입니다. 한 행에서 둘 이상이 1이거나 모두 0일 수 있습니다. 각 분할의 각 라벨 열에는 0과 1이 모두 있습니다.

`(97,3)` 형태의 실수 확률을 반환하며 열 순서는 유지합니다. 각 원소는 0~1이어야 하지만 **행 합이 1일 필요는 없습니다**. 평가지표는 라벨별 ROC-AUC를 평균한 Macro ROC-AUC입니다. argmax·원-핫 벡터·단일 라벨 제출은 요구하지 않습니다.

### 힌트

출력이 세 개라고 무조건 CrossEntropyLoss를 쓰지는 않습니다. 이 문제에서는 각 노드가 해당 상태의 존재 여부를 따로 예측하므로 BCEWithLogitsLoss를 사용합니다.

### 치트시트 수정 매뉴얼

1. [다중분류와 다중 라벨 분류](/playbook/08/)을 엽니다. B01과 비교하면서 차이를 세 군데 표시하세요: 정답 형태, 문제 유형·손실함수, 추론 시 변환.
2. 표형 전처리는 B01과 동일합니다. y는 이미 `(N,3)` float이므로 searchsorted·LabelEncoder·argmax를 적용하지 않습니다.
3. `h.MLP(Xtr.shape[1],3,hidden=(32,16),dropout=0)`, `task="multilabel"`로 설정합니다. 모델은 변환 전 로짓 `(N,3)`을 출력합니다.
4. 평가 콜백은 로짓에 sigmoid를 적용한 뒤 `roc_auc_score(truth, probability, average="macro")`, maximize=True입니다. 검증 데이터의 라벨 열 하나가 한 값만 가지면 AUC가 정의되지 않으므로 학습 전에 분포를 검사합니다.
5. 공통 실행 블록에서 return_proba=True를 사용해 `(N,3)` sigmoid 확률을 반환합니다. 행 합을 1로 정규화하지 않습니다.
6. `--case B07`로 저장합니다. 세 열의 순서를 알파벳순으로 바꾸거나 ‘가장 큰 확률’ 한 열만 남기면 잘못된 제출입니다.

### 해설과 재도전

참고 풀이 `CASE B07`을 B01과 나란히 읽으세요. B01의 각 행에는 하나의 정수 정답이 있고 B07에는 각 상태에 대한 정답이 세 개 있습니다. 같은 출력 노드 수 3이어도 손실함수와 추론 시 변환이 달라집니다.

재도전: `[0.8,0.7,0.2]`가 유효한 예측인 이유를 설명하세요. 임계값 .5를 적용하면 두 상태가 켜지지만, B07에서는 임계값을 적용하기 전 확률을 제출합니다. 검증 데이터에서 라벨별 AUC도 출력해 평균에 가려진 낮은 성능을 찾으세요. 임계값별 F1은 별도의 진단 지표이며 이 문제의 모델 선택 지표는 아닙니다.

자주 나는 오류는 softmax로 상태 간 경쟁을 강제하는 것, CE를 쓰려고 y에 argmax를 적용하는 것, BCE에 long형 y를 전달하는 것, 정확도만 확인하는 것, 클래스 확률의 합이 1인지 검사하는 assert를 그대로 사용하는 것입니다.
