Problem · 기본 · 권장 40분. 숫자가 큰 클래스가 양성이라는 무의식적 가정을 깨는 문제입니다.

문제와 입출력 조건

B01과 표형 구조와 행 수가 같은 합성 데이터입니다. y의 원래 값은 고장=2, 정상=5입니다. 요구하는 것은 고장일 확률 P(y=2)입니다. 훈련·검증에는 두 클래스가 모두 있으며, 입력의 결측값과 테스트의 미지 범주 D도 있습니다.

(97,1) 형태의 0~1 범위 실수 확률을 반환합니다. 지표는 고장=2를 양성으로 계산한 ROC-AUC이며 클수록 좋습니다. 2/5 라벨, 0/1 분류 결과, 정상일 확률, 두 열짜리 확률은 이 문제에서 요구하는 출력이 아닙니다.

힌트 펼치기

정답을 (y==2).astype(float)로 바꾸세요. LabelEncoder 기본 정렬 결과만 믿으면 2가 0에 대응하므로 양성 의미가 뒤집힐 수 있습니다.

치트시트 수정 매뉴얼 펼치기
  1. 이진분류·확률 제출와 형태·손실함수 표를 엽니다. 입력 전처리에는 훈련 데이터로만 학습하는 B01의 함수를 재사용합니다.
  2. ytr=(data["y_train"]==2).astype(np.float32).reshape(-1,1)로 만들고 검증 정답에도 동일하게 적용합니다.
  3. h.MLP(Xtr.shape[1],1,hidden=(32,16),dropout=0), task를 binary로 둡니다. 학습 손실함수는 BCEWithLogitsLoss이므로 모델 끝에 Sigmoid를 붙이지 않습니다.
  4. AUC 평가 콜백에서 변환 전 로짓에 sigmoid를 적용한 값과 0/1 정답 truth를 비교합니다. maximize=True입니다. AUC 계산을 위해 임계값 .5로 0/1을 결정하면 순위 정보를 잃습니다.

import torch
from sklearn.metrics import roc_auc_score
def score_fn(truth, raw):
    probability = torch.sigmoid(torch.from_numpy(raw)).numpy()
    return roc_auc_score(truth.reshape(-1), probability.reshape(-1))
  1. 공통 실행 블록의 return_proba=True는 추론할 때 sigmoid를 한 번 적용합니다. 그 결과에 다시 sigmoid를 적용하거나 라벨로 복원하지 말고 그대로 반환합니다.
  2. --case B06으로 검사합니다. 평균 확률이 0.5 근처인지만 보지 말고 검증 데이터의 양성·음성 점수 분포와 AUC의 방향을 확인하세요.
해설과 재도전 펼치기

참고 풀이 CASE B06와 predict_torch에서 이진분류 확률을 만드는 부분을 함께 확인하세요. ‘BCE 손실함수에는 로짓, 제출에는 확률’이 핵심입니다. 이 문제는 확률 보정 성능이 아니라 AUC로 순위를 평가하지만, 반환값은 0~1 확률이어야 합니다.

항상 같은 확률을 예측하면 AUC는 0.5입니다. 재도전: 검증 데이터에서 p와 1-p의 AUC를 비교해 양성 방향을 확인합니다. p의 성능이 좋지 않다고 테스트 점수를 보고 뒤집지는 마세요. 어느 쪽을 양성으로 볼지는 문제의 라벨 정의에 따라 정해야 합니다.

자주 나는 오류는 5를 양성으로 학습하는 것, BCE 정답에 정수형 long을 쓰는 것, 모델 안팎에서 sigmoid를 두 번 적용하는 것, return_proba=False로 임계값을 적용하는 것, (N,) 형태로 저장하는 것입니다.
